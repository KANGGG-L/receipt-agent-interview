## 一、30 秒电梯稿（开场定调）

> "这个项目做的是香港中小餐饮商户的进货单据智能识别与库存入库 SaaS。香港 1.6 万家食肆里，74.9% 的进货单是街市手写单——无表格、油污、繁体草书、司马斤混算，传统 OCR 实测成功率只有 3.1%，老板每天手工录单、月底通宵对账。我负责把这个模块从 0 到 1 做出来：用多模态大模型解决'读不懂'的问题，用确定性代码门禁解决'敢不敢信'的问题，最终单张录入从 5 分钟压到秒级预填+复核，163 张真实单据实测解析成功率 100%、财务字段零算术错误。"

**核心定位**：不是"做了个 OCR"，而是"在一个 AI 是唯一解的场景里，把概率模型驯化成财务级可信系统"。这句定调直接呼应简历"个人优势"第一条（AI 原生增量价值定义）。

## 二、2 分钟完整 STAR

### S 情境
在 PGM 做 AI PM，公司要做餐饮一体化 ERP，但发现"进货数据没人录"是整个 ERP 的死穴——GIGO：没有准确及时的进货数据，毛利分析、智能补货全部空转。走访深水埗茶餐厅、旺角中菜馆、油麻地菜档后确认：手写单占 74.9%、人工录入 5 分钟/张且错漏率 10%~15%、月底对账耗费 15~20 小时。（证据：step1-机会洞察 PT-1~PT-8 痛点矩阵、step2-问题验证 Gemba 走访档案）

### T 任务
作为子模块产品负责人，在 12 周（2026.05.06–07.31）内让店员实现"拍照 → 几十秒核对 → 入账"的全流程闭环，并建立可度量、可回归的评测与治理体系。

### A 行动（三条主线）
1. **选型有据**：搭建统一评测台（固定 temperature=0.01、prompt sha256 钉制、holdout 密封切分），10 级技术阶梯 L0-L9 逐一实测归因，用数据否决了三个"看起来更聪明"的方案（L5 模板路由、L7 看想分离、L9 微调范式）。
2. **架构分层**：三层互不信任——VLM 输出一律视为不可信草稿；Pydantic 契约 + Python 算术守恒门禁（数量×单价=金额）只校验建议、不静默改写；只有老板 Approve 才触发唯一的 Append-Only 台账写入。
3. **体系闭环**：57 张黄金样本集（Dev 46 调参 / Holdout 11 密封防过拟合）、11 个服务端全生命周期埋点、北极星指标=每周每店成功入库单数、灰测 A/B 实验带双比例 z 检验与最小样本量门禁、P0-P2 分级熔断预案。

### R 结果
- 163 张真实单据（batch1）解析成功率 **100%**（Tesseract 仅 3.1%，数量级差）
- 对抗性幻觉样本（50 组）门禁拦截率 **100%**，零静默改写
- 自动化测试 **587 passed / 0 failed**，8 条端到端 DoD 全绿
- 五个实施阶段（安全底座→AI 可见性→数据度量→供应商纵深→Agent 化）终判**阻塞项为 0**
- 阶段 0–4 全链路产品终验综合 **4.92/5.0 ACCEPT**，v2.6 版四大场景 PM 验收 **98/100 准予全量上线**
- 单张识别成本约 **HK$0.0024（0.24 港仙）**，月均单店 API 支出不足 HK$1.00，毛利率 >90%

| LangGraph 这类图编排为什么不用？ | 识别流程本质是"确定性流水线 + 局部错误反馈自愈"；线性编排完全可单测、无死循环、故障秒级定界。探索期允许 LLM 编排器（枚举动作空间+决策日志蒸馏），生产期回落纯代码 Supervisor，每条规则都有蒸馏来源日志 | ai/02 方案第十节 D37 |

### 加分延伸储备（聊开时的纵深）

- **指标体系**：北极星=每周每店成功入库单数（天然过滤"上传量"虚荣指标，Approve 是内建质量门槛+续费先验信号）；FER 字段编辑率、Zero-Edit Rate、审核采纳率、幻觉率四指标精确定义 + ai_decision_log/ai_metric_snapshot 两表建模 + 采样<30 标灰机制。
- **A/B 实验**：双比例 z 检验 p<0.05 且效应量>MDE 才允许 promote；最小样本量不够端点直接拒绝结题返回 INSUFFICIENT_SAMPLE；护栏指标任一恶化禁推全。
- **灰度分流四级路由**：总开关 → allowlist 白名单 → 单据概率 → 供应商 Hash（保同供应商记忆连贯）；推全自动生成 rollback_snapshot，回滚 <50ms。
- **"最难排查的 bug"标准答案**：脱敏正则优先级——手机号正则先匹配吃掉了 18 位身份证中间的 11 位生日段 → 加 `\b` 词边界 + 重构执行优先级（身份证全局优先），活体服务器构造双字段真实单据回归验证。
- **延迟治理最新战果**（可选讲）：曾出现 ~4 分钟/张的性能回归，根因是审核腿挂了慢速本地模型撞 240s 超时；通过 audit 引擎切换 DashScope 快速通道 + 超时收紧至 90s + text 审核模式，实测降到 4~5.5 秒/张。

## 五、与另两个项目的故事衔接

- **共同主线**（贯穿三段经历的个人方法论）："概率模型交给 AI，确定性交给代码"——本项目是算术守恒门禁，SpaceFinAgent 是规则引擎数值校验 + Critic Agent 双防线，Serenity-SupplyNet 是结论×证据×原文切片强制挂链硬闸。让面试官自己总结出你的 consistency。
- **递进关系**：OCR 项目证明"单一脏数据入口的可信化"（感知层信任问题）→ SpaceFinAgent 上探"决策支持与监管合规"（推理层信任问题）→ SupplyNet 展示"多 Agent 协作与知识资产沉淀"（协作层信任问题）。复杂度递增，底层哲学不变。
- **若被问"最有含金量的挑战"**：首推本项目——它是唯一从 Gemba 调研 → 选型实测 → PRD 定稿 → 分阶段实施 → 对抗终判 → PM 验收报告全程留痕的项目，每个数字都有文档可回溯。

## 六、高频开放题速答

| 问题 | 30 秒答案要点 |
|---|---|
| 你最大的贡献是什么？ | 不是写了多少 prompt，而是建立了"用数据否决直觉"的选型方法论（10 级阶梯归因）和三层互不信任架构——后者让系统在任何模型升级时都保持财务可信 |

| AI 替代了谁的工作？ | 不是替代录入员，而是角色质变：从"手工录入员"变成"审核背书员"——这符合香港后厨老龄化、年轻人拒做机械抄录的现实 |
| 业务价值如何量化？ | 老板视角：每月省 20 工时对账 + 拦截数千元错账与隐性涨价；公司视角：UE 模型毛利率 >90%、LTV/CAC 约 7~8x、回收周期 <5 个月 |
