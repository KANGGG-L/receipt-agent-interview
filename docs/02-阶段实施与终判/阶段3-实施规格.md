# 阶段 3 实施规格｜供应商深度与对账

> 目标：解开"敢不敢共享"和"对账是不是自证其真"两个堵点。补齐商户维度查阅。
> 前置依赖：阶段 0（脱敏视图）、阶段 1（use_grey 持久化）、阶段 2（指标体系 + 漏斗，可选依赖）。
> 预计周期：2-3 周。

## 3.2 验收标准

1. 从供应商档案卡"单据数"可一键进该供应商收据时间线（脱敏可选）
2. 灰测选"按供应商名单"模式，仅勾选供应商进灰测
3. 对账能暴露"供应商账单 1000，系统单据 980"差异并定位差异单据
4. 成本报表用加权平均，与"最新单价×库存"有可解释偏差
5. 导出 CSV 走脱敏

## 3.3 测试方法与预期结果

- T3.1 `GET /api/suppliers/5/receipts?desensitized=true` → 该供应商全部单据 + 月度进货额趋势
- T3.2 `grey_supplier_ids=[3,7]` + `assign_mode=allowlist` → 仅 supplier 3/7 的单据 `use_grey=true`
- T3.3 导入月结账单 1000，系统单据合计 980 → 对账结果 diff=20，列出差异单据 id
- T3.4 同批入库两次（5 元×10、8 元×10），查成本 → 加权平均 6.5 而非 8

## 3.4 关键设计约束

1. 供应商详情页复用了阶段 0 的脱敏端点
2. allowlist 与现有按供应商一致性分桶（hash bucket）是两种模式，UI 明确区分
3. 对账端点要留操作审计（阶段 0 的 system_audit_log）
