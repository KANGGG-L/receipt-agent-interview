## 4.2 验收标准

1. 对话查询能回答跨表问题（join 供应商+库存+成本）
2. 复盘链输出含具体供应商名 + 趋势 + 建议动作
3. VendorMemory 写入后同供应商再次识别准确率有可测提升（阶段 2 指标体系可验证）
4. 模糊图片上传被拦截并给重拍提示，quality_warnings_json 写入
5. 复盘结果以卡片呈现非 JSON 表格

## 4.3 测试方法与预期结果

- T4.1 输入"上月菜心单价最高的三家供应商" → 返回 3 家 + 单价 + 单据数
- T4.2 注入某供应商菜心本月涨 40% → 复盘链输出"供应商 X 菜心涨 40%，建议核实/谈判"
- T4.3 同供应商第一张单识别错纠正后第二张 → 第二张准确率提升（VendorMemory few-shot 生效）
- T4.4 上传模糊图片 → HTTP 400 + msg="图片模糊，建议重拍"，quality_warnings 写入
- T4.5 触发复盘 → 前端渲染异常卡片/趋势卡片/建议卡片

## 4.4 关键设计约束

1. 对话查询要留审计（谁问了什么、AI 答了什么）
2. RAG 用现有 `VendorMemory` 模型，写入时机在 approve 后
3. 图片质量预检用轻量 heuristic（不依赖外部服务）
