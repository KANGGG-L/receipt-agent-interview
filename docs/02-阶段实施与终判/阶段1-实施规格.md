## 1.4 实施细节（开发指引）

### 1.1 审核 reason 字段

**audit_chain.py 改动**：在异常判定返回时附带 `reason`。格式示例：
```python
# 单价异常
reason = f"单价 {unit_price} 元，比 {supplier} 过去 30 天均值 {avg:.2f} 高 {pct:.0f}%"

# 数量异常
reason = f"数量 {qty} {unit}，该商品历史最大单次 {max_qty}，偏离 {deviation}x"

# 金额小数异常
reason = f"小计 {amount} 与 qty({qty}) × price({unit_price}) = {expected} 不符"
```

**数据结构**：`audit_result` 从 `dict` 扩展为：
```python
{
  "status": "ok" | "flagged",
  "reason": str | None,        # 人类可读，新增
  "anomalies": [               # 具体异常点
    {"field": "unit_price", "severity": "high", "detail": str}
  ],
  "confidence": float,
}
```

### 1.2 对照 UI

**交互**：单据编辑页增加"AI 识别结果 vs 当前值"对照区（三栏表）：
- 列 1：字段名（商品名/数量/单价/小计/供应商）
- 列 2：AI 建议值（来自原始识别）
- 列 3：当前值（用户改后）
- 操作：每行一个"采纳 AI"按钮，点击后该字段恢复为 AI 值并记录采纳事件

**前端埋点**：采纳事件写入 `user_event`（阶段 2 定义，阶段 1 先写 raw，阶段 2 接入事件表）：
```
event_type: 'ai_suggestion_adopted'
properties: {field, ai_value, user_value_before}
```

### 1.3 use_grey 持久化

**db.py**：`ReceiptRow` 增加 `use_grey: Integer` 列。`create_receipt/set_receipt` 时传参。迁移走 Alembic（阶段 0 的 m2 已建议，阶段 1 正式引入）。

**supervisor.py**：识别前调 `should_use_grey(cfg, supplier_name)`，结果写入 receipt 行。改完确保 0.3 脱敏端点能正确过滤 use_grey 维度。

**前端**：单据卡片右上角标签 "灰测组处理"（黄色），hover 显示"如果用常规模型会怎样"（若同时跑了对照）。

### 1.4 AI 发现卡片

**review_chain.py**：增加 `weekly_insights()` 方法，输入 cost_summary，输出：
```python
{
  "top_price_risers": [{"supplier": "XX", "item": "菜心", "pct": 40, "period": "7d"}],
  "anomaly_count": 12,
  "suggestions": ["XX 供应商菜心涨价 40%，建议核实", "本周异常单据 12 张，建议优先复核"]
}
```
缓存 1 周，避免重复计算。

**首页渲染**：待办区上方插入"AI 发现"卡片，每条可点击跳对应供应商详情页（阶段 3）。

## 1.5 与阶段 2 的接口约定

阶段 1 埋的采纳/对照事件，阶段 2 会接入 `ai_decision_log` 表计算准确率/修正率/信任度。因此：

- 采纳事件必须含 `receipt_id, field_path, ai_value, user_value, ts` 五元组
- `user_grey` 必须在写入前就定下来（不能改），阶段 2 按它分组对比
