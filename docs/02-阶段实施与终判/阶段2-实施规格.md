## 2.2 验收标准

1. 任意时间窗可查准确率/幻觉率/修正率/信任度，支持按供应商/引擎/模型/实验分组
2. 灰测效果对比面板能回答"灰测组准确率比常规组高/低 X 个百分点"
3. 漏斗每一步转化率可查，卡点步骤高亮
4. 推全后回滚能同时恢复常规组与灰测组（阶段 0 已含快照，本阶段加灰测组快照）

---

## 2.3 测试方法与预期结果

- T2.1 注入 100 张单据（50 常规 50 灰测，含已知正确答案）→ `GET /api/admin/ai-metrics?group=treatment` 返回 accuracy/hallucination_rate/edit_rate 三个数值；样本<30 标灰
- T2.2 灰测组准确率 92%、常规组 85% → 效果对比面板显示 +7pp，建议推全
- T2.3 漏斗：上传 100→解析 95→编辑 80→审核 75→审批 70→入库 68 → 各步转化率显示，"编辑→审核"卡点标红
- T2.4 promote 后立即 rollback → 常规组与灰测组字段均恢复为 promote 前值（model_dump diff 验证）

## 2.4 关键设计约束

1. `ai_decision_log` 表必须含 `experiment_id, grp, engine, model, use_grey, decision_type, field_path, ai_value, user_value, adopted, confidence, is_hallucination` 列（对齐指标体系规格）
2. 采纳判定必须在 approve 时回填（不是 save_edited），因为用户可能改了又改
3. A/B 结题需 z 检验 p<0.05 + 效应量>MDE + 样本≥min_sample + 护栏指标不恶化
4. 漏斗配置可配（JSON），非写死

## 2.5 不做的事

- 不做供应商详情页（阶段 3）
- 不做前端对照 UI 采纳事件的重构（阶段 1 已在 audit_logs_json 过渡存储，本阶段迁入 ai_decision_log）
