# 06 · 跟开发沟通和跟进（Dev Communication & Follow-up）

> 本项目的开发协作以「书面留痕 + 证据驱动」为原则：需求用 AC 文档、跟进用 issue 工单与实施计划、纠偏用根因定位 + 修复指引。本文档提炼沟通机制与三个真实沟通案例。

---

## 1. 沟通机制总览

| 场景 | 载体 | 留痕物 |
| :--- | :--- | :--- |
| 需求传递 | AC 规格书（量化、可判负） | `docs/05-AI产品体系与模块Spec/05-增量模块PRD与ACSpec/EXPORT_CENTER_PRD_AC_SPEC.md` 等 |
| 任务分派 | 实施计划（T-Task + checkbox） | 特性级实施计划（已随仓库清理移除，过程留痕见 git 提交史） |
| 缺陷跟进 | Issue 工单（现象/根因/修复/验证四段式） | `docs/issues/` × 4 |
| 阶段同步 | 三方对抗评审（开发/QA/产品互审） | `docs/02-阶段实施与终判/` |
| 跨周期交接 | 交接说明沉淀在 git commit message 与 `docs/issues/` 工单闭环记录中 | `docs/issues/`、git 提交史 |
| 日常跟进 | commit message 规范（feat/fix/test/docs + 模块 + 业务语义） | git 提交史 |

**跟进节奏**：每个特性走「设计 spec → 实施计划 → 逐 T 开发 → 完成即勾选 checkbox → 文档对账」，欠账不进周末（commit `92fec08`/`01cf8e9` 可见 checkbox 勾选与「文档对账 19 条」收口）。

## 2. 案例一：技术方案被用户当场指正（纠偏类沟通）

**背景**：识别与审核双腿引擎改造中，开发将审核腿默认模型迁至 SiliconFlow DeepSeek（commit `fa572ab`）。

**问题**：DeepSeek-V3.2 是纯文本模型，不能审图片。该方案在向用户演示时被当场指正。

**PM 处理**：
1. 不辩护、先确认事实（审核腿的输入是收据图片）。
2. 当天与开发对齐替代方案：切换 GLM-4.5V（视觉模型），并支持 text/vlm/ondemand 三种审核模式（commit `bacab8c`，消息中明确写了「非视觉,用户指正」——错误不掩埋）。
3. 补「强制装配语义补丁」：模型解析不再读 DB 旧值，重启必回标准双腿（commit `1170333`），把「人会忘」变成「系统不会错」。

**经验**：纠偏沟通的落点不是「谁对谁错」，而是把教训固化成系统约束。

## 3. 案例二：QA 驳回后的修复跟进（质量冲突类沟通）

**背景**：Round 2 UAT 驳回（DEFECT-01 弹窗选择器错位 / DEFECT-02 币种混杂），见 05 文档。

**PM 处理**：
1. 驳回报告不是情绪表达，而是**工作交接物**：根因定位到 `main.js` 具体选择器 + 修复指引。
2. 明确修复验收口径：复验以同一 TC 编号重跑，证据截图归档。
3. 修复完成后 Round 1 同期的引擎改造（opencode 退役全面 SiliconFlow 化）也一并收口（commit `a29a43a`），避免多头等待。

**经验**：驳回 + 高质量缺陷信息 = 最快的修复路径；冲突被转化为信息增益。

## 4. 案例三：数据真实性的向上沟通（原则坚持类）

**背景**：专项调查发现观测台灰测指标被"美化"——用 `id%2` 伪造分组、拿用户录入数据伪造「AI 预填镜像」刷出 100% 采纳率（P0），AB 实验 p 值算出 1.1064（P1）。见 09 文档。

**PM 处理**：
1. 定性为诚信问题而非普通 bug：指标失真会让所有下游决策（放量、迭代方向）建立在假数据上。
2. 推动按 P0-P3 分级修复，全部 7 项带回归用例收口，且**如实标注遗留项**（math_gate_passed 置 null、无 ai_prefill 时采纳率显示「无法比对」）而不是悄悄藏掉。
3. 工单归档 `docs/issues/2026-09-02-observatory-truthfulness-fixes.md`，留痕可审计。

**经验**：跟开发沟通最难的不是催进度，是让「如实呈现坏消息」成为团队默认行为——PM 要先自己做到（红灯如实落档，commit `536785f`）。

## 5. 跨职能沟通的纪律清单

1. **所有结论落到可执行物**：会议/沟通的出口永远是 spec、AC、issue 或 checkbox，不产生"口头共识"。
2. **commit message 写业务语义**：`fix(engine): 审核腿默认改GLM-4.5V——视觉模型支持...(用户指正)`——未来任何人不读代码也能还原决策链。
3. **坏消息优先**：红灯（元评测未达标）在落档时如实标红，不粉饰。
4. **交接对账制**：交接说明沉淀在 git commit message 与 `docs/issues/` 工单中，用逐 commit 变更表 + 「验收欠账/剩余任务/已知坑」三清单，让接手人 30 分钟进入状态。

---

## 面试叙事要点

- 用案例一讲**向上沟通的勇气**与向下纠偏的系统化（用户指正 → 48h 内换模型 + 系统级防复发）。
- 用案例三讲**数据诚信**：PM 的职责边界不只在需求，还在「不让仪表盘说谎」。
