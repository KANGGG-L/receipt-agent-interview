# 03 · Acceptance Criteria（验收标准）

> AC 是本项目需求侧的核心管理抓手。两份真实 AC 规格书是主要证据：`docs/05-AI产品体系与模块Spec/05-增量模块PRD与ACSpec/EXPORT_CENTER_PRD_AC_SPEC.md`（导出中心 AC-1~AC-12）与 `docs/05-AI产品体系与模块Spec/05-增量模块PRD与ACSpec/DISHE_MODULE_REPAIR_AC.md`（餐品模块修复 AC-1.1~AC-8.5）。本文档提炼 AC 的**写法、分级与追踪闭环**。

---

## 1. AC 体系设计

```
PRD 用户故事
  └─ Feature 级 AC（编号 AC-x，量化可判）
       └─ 缺陷修复 AC（编号 AC-模块.序号，如 AC-2.1 跨租户隔离）
            └─ 测试用例（04 文档）─→ UAT 执行记录（05 文档）
```

**AC 写作纪律（三条硬规矩）**：
1. **可量化**：不写「界面友好」，写「触控目标 ≥38px、对比度 ≥ WCAG AA (4.5:1)」。
2. **可判负**：每条 AC 必须能构造一个让它 FAIL 的输入。AC-2.1 跨租户隔离的 FAIL 输入就是「用 A 租户 token 请求 B 租户 SKU」。
3. **有 owner 与验证方式**：单测 / E2E / 真机 UAT 三选一或组合。

## 2. 样例：导出中心 AC（摘自 EXPORT_CENTER_PRD_AC_SPEC.md）

| AC | Given / When / Then | 验证方式 |
| :--- | :--- | :--- |
| AC-1 | Given 店员角色，When 请求越权报表，Then 返回**人话版 403**（说明原因与申请路径），非裸错误码 | 单测 + 真机 |
| AC-4 | Given 任意含中文的报表，When 导出 CSV 用 Excel 打开，Then 无乱码（**UTF-8 BOM 强制**） | 真机 UAT |
| AC-6 | Given CSV 单元格以 `=`/`+`/`-`/`@` 开头，Then **公式注入防御**转义，Excel 打开不执行 | 安全单测 |
| AC-8 | Given 同一用户重复导出，When 对比两次文件，Then 脱敏口径**一致**（金额掩码规则统一） | 对拍测试 |
| AC-10 | Given 触屏设备，When 操作所有导出按钮，Then 触控目标 **≥38px**，WCAG AA 对比度达标 | UI 审查 + Playwright |

（完整 12 条见 `docs/05-AI产品体系与模块Spec/05-增量模块PRD与ACSpec/EXPORT_CENTER_PRD_AC_SPEC.md` §5，含四类用户画像、14 套报表业务规格与交互边界异常。）

## 3. 样例：缺陷修复 AC（摘自 DISHE_MODULE_REPAIR_AC.md）

修复类 AC 的写法要点：**先写根因与影响矩阵，再写目标行为**，让开发不用猜。

| AC | 缺陷根因 | 目标行为（Then） | 结果 |
| :-- | :--- | :--- | :--- |
| AC-1.1 双轨库存漂移 | 消耗写入未同步 FIFO 台账 | 库存余量与 FIFO 台账**逐笔一致**，差异为 0 | ✅ 25 项单测全过 |
| AC-2.1 跨租户隔离 | BOM 查询缺 tenant 过滤 | A 租户无法读取/引用 B 租户 SKU 与配方 | ✅ 租户隔离测试通过 |
| AC-3.1 负数拦截 | 输入校验缺失 | 负数数量在**前端与后端双重拦截**，给出人话提示 | ✅ |
| AC-4.1 半份支持 | 整数假设 | 支持 0.5 等半份小数，账目精度一致 | ✅ |
| AC-5.1 跨量纲熔断 | 单位换算缺失 | kg ↔ 件 换算无定义时**熔断报错**而非静默算错 | ✅ |
| AC-7.1 店员只读 RBAC | 角色未下沉到接口层 | 店员对成本/治理接口只读，UI 无入口且 API 拒绝 | ✅ |
| AC-8.x 触控人机工程 | 按钮过小 | 触控目标 38px（列表）/42px（主操作），防误触 | ✅ Playwright 全流程过 |

## 4. AC → 测试 → UAT 追踪闭环（真实案例）

**案例：QA Round 2 一票否决**

```
D-AC（店员弹窗行为）
  → 测试用例 TC-08「关闭只读弹窗」
  → UAT 执行发现 DEFECT-01：main.js querySelector 误命中 header 的 x 按钮
  → 测试结论 [FAIL 驳回修复]，附根因定位与修复指引
  → 开发修复后复验通过 → AC 关闭
```

另一案例：**币种一致性 AC** 在 Round 2 发现人民币 ¥ 与港币 $ 混杂（DEFECT-02）——该 AC 在 Round 1 的代码审查中未被覆盖，证明「真机 UAT 是 AC 的最后一道闸」。

## 面试叙事要点

- **AC 可判负原则的由来**：早期 AC 写过「导出体验良好」这种无法验收的句子，QA 无法执行，后来强制量化（BOM、38px、AA 对比度），Round 1 测试 31 项才能做到「每项都有唯一判定」。
- **修复类 AC 的模板价值**：`DISHE_MODULE_REPAIR_AC.md` 的「根因→影响矩阵→AC→测试矩阵→实施路线」结构被复用到后续所有缺陷治理（如观测台 P0-P3）。
