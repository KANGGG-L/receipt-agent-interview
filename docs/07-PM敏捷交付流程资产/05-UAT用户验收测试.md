# 05 · UAT（用户验收测试）

> UAT 是本项目放行的最终闸门，形式为 **QA_Agent 在隔离实例上独立真机实操**（非看代码、非看单测报告）。两轮真实 UAT 是核心证据：Round 1 导出中心 UAT（31 项全绿 PASS，原始报告未归档）与 Round 2 复验报告 `docs/09-测试与UAT报告/test_report_qa_round2.md`（FAIL 驳回 → 修复 → 复验通过）。

---

## 1. UAT 机制设计

| 要素 | 约定 |
| :--- | :--- |
| 执行者 | QA_Agent（独立于开发，只用浏览器黑盒操作） |
| 环境 | 隔离实例（如 Round 2 使用端口 15012 独立副本，不污染主库） |
| 入口 | 开发自认 PASS 后提交 UAT 申请 + 变更清单 |
| 判定 | 逐项 PASS/FAIL，一票否决项见 04 文档 §5 |
| 存证 | 每个缺陷附截图 + 根因定位 + 修复指引 |
| 出口 | `[PASS 准予交付]` / `[FAIL 驳回修复]` 二元结论，无「有条件通过」 |

---

## 2. Round 1：导出中心 UAT（2026-09-03，PASS）

**范围**：统一报表与导出中心，14 套报表 × 4 类用户角色。

**31 项全绿，亮点**：
- 功能：14 套报表导出齐全、UTF-8 BOM 防乱码、A4 盘点底单手填列与三级签名栏。
- 安全：CSV 公式注入防御、脱敏一致性、多租户隔离、RBAC 人话拦截。
- 体验：触控 ≥38px、WCAG AA 对比度实测 **5.17:1**。

**结论**：`[PASS 准予交付]`。

---

## 3. Round 2：餐品模块 UAT（2026-09-03，FAIL 驳回）

**范围**：餐品与消耗模块（BOM 配方 / FIFO 成本 / 消耗记录），对照 `docs/05-AI产品体系与模块Spec/05-增量模块PRD与ACSpec/DISHE_MODULE_REPAIR_AC.md` 的 8 组 AC。

**结果**：31 项中 29 PASS，**2 项一票否决 FAIL**：

| 缺陷 | 现象 | 根因定位（QA 给出） |
| :--- | :--- | :--- |
| DEFECT-01 | 店员只读弹窗点关闭，误关页面头部 | `main.js` 中 `querySelector` 选择器作用域错位，误命中 header 的 x 按钮 |
| DEFECT-02 | 币种混杂：同一页面人民币 ¥ 与港币 $ 混排 | 金额渲染未统一走币种配置单源 |

**处置**：
1. 当轮结论 `[FAIL 驳回修复]`——29 项 PASS 不抵 2 项红线，拒绝签字放行。
2. 报告附根因定位与修复指引，开发按指引修复。
3. 修复后复验：DEFECT-01/02 关闭，模块最终交付。

**流程价值**：这轮 UAT 证明了「代码层测试全绿 ≠ 用户可用」。DEFECT-01 在 25 项单测 100% 通过的情况下依然存在，只有真机点按才能暴露。

## 4. UAT 与前序测试的分工

```
开发自测（pytest/Playwright）→ 逻辑正确
QA UAT（真机黑盒）          → 交互可用、角色视角正确、视觉一致
PM 终审（receipt_agent_pm_acceptance_report.md）→ 业务闭环与数据真实
```

三层各自能放行什么、拦住什么，职责边界清晰；Round 2 恰好是第二层拦住第一层漏网缺陷的实证。

## 5. UAT 报告模板（沉淀为团队规范）

```markdown
# UAT 报告：<模块名> Round <N>
- 日期 / 执行者 / 环境（隔离实例端口）
- 依据 AC：<AC 文档链接>
- 结论：[PASS 准予交付] / [FAIL 驳回修复]
- 逐项结果表：TC ID | 用例 | 结果 | 证据截图
- 缺陷清单：ID | 现象 | 根因定位 | 修复指引 | 复验状态
- 遗留与建议
```

---

## 面试叙事要点

- **敢驳回**：29/31 PASS 且开发催交付时，仍以两项一票否决驳回——质量闸门的价值在于「否决权真实存在」。
- **驳回要有建设性**：不是打回重做，而是附根因定位 + 修复指引 + 截图存证，让修复在半天内完成——**驳回的成本被压到最低**。
- **隔离实例纪律**：UAT 永远打独立副本（15012 端口实例），测试数据不污染主库——展示环境治理意识。
