## 1. 审查范围与方法

- 工具：Python Playwright 1.x + Chromium headless，视口 desktop 1440x900、mobile 390x844（is_mobile + has_touch），另抽测 412/600/641/768 宽度。角色通过 localStorage `demo_role` + 页面下拉切换（与界面实际机制一致，main.js:14024-14044）。
- 实操流程：
  - staff：选择图片 → 图片编辑卡 → 开始 AI 智能解析 → 失败卡 → 点"转手工补录" → 点"新建手工单" → 制造 数量×单价≠金额（10×4.5 填 50）、总额对不上（明细 50 / 总额 60）→ 提交 → 修正 → 再提交。桌面与手机各跑一遍。
  - 长等待：真实识别 1.3s 内就失败（无 key），看不到长等待。所以用 `page.route('**/api/job/**')` 让轮询连续 75s 返回 `running`，采样 3/15/30/45/60/72s 时的 UI（waitsim.py）。
  - owner：待我审批 → 打开单据 → 带错审批 → 改完未保存审批 → 保存 → 审批确认弹窗 → 入账；库存 详情/价格走势/盘点/变动录入/编辑/更多/新增/管理库存；归档 详情/标记异常/新增供应商/编辑/更多(合并)/登记支付/发起对账/查看对账详情；部门花销查询/新增部门；数据中心导出 CSV；owner 上传失败路径 + 放弃上传。
  - admin：系统与引擎配置 3 个子页、观测中心 4 个子页、/evalset（admin 与 staff 两种身份）。
- 量测：所有可见按钮/select 的 boundingBox 高度、WCAG 对比度（逐个文本节点算前景/背景）、字号 <12px、label 关联、主滚动容器（`.main-wrapper`）与表格的横向溢出、键盘 Tab 顺序与焦点样式、11 个弹窗的初始焦点/Tab 陷阱（25 次 Tab）/Esc 关闭、console error/warning、HTTP >=400、CDP 限速（4G 9Mbps/60ms、3G 1.6Mbps/150ms）下的 FCP/DCL。
- 没覆盖的及原因：
  - 真实 AI 成功路径（预填 → 复核 → 入账，没有 LLM key），所以"不到一分钟"只能按步骤数估算。
  - 付款提醒横幅（库里没有逾期或快到期的赊单，`#payReminderBanner` 一直隐藏）。
  - 供应商合并（"更多"菜单里没找到合并入口，看 screens/S3-desk-owner-O09-sup-more.png，待验证入口位置）。
  - 真机 iOS/Android 拍照（只能核对 `capture` 属性）。
  - /evalset/workbench（评测集 manifest 不存在，没有样本）。
- 数据说明：服务是共享的，其他审查员同时写入了数据（如 S4 的 XSS 供应商名）。本审查新建了收据 #16-#24（失败上传与手工单），审批了 #19，把 #21 标记为异常，放弃了 1 张 owner 上传。没有删库、没有停服务。

## 6. 做得好的地方

- 算术差额提示是人话，有具体金额，也不怪画质："明细各项金额加总 ($50.00) 与整单总金额 ($60.00) 不符，相差 $10.00 元。请对照原图核对各行金额，或修改总金额"（main.js:6871）。配合"下一处问题 / 仅看问题行"按钮，定位很方便。
- 审批入账的确认弹窗信息完整（单号/品名/供应商/金额/待核对问题数），按钮动词明确"确认入账并增加库存"；没保存、有阻断问题时都会拦截。
- 弹窗键盘体验：11/11 能用 Esc 关闭，Tab 不会逃出弹窗，焦点轮廓 2px 蓝色清晰。
- 识别中常驻"等不及？点击取消并转手工补录"，失败卡写明"这不是照片的问题，请不要重新拍照。原图已保留"。owner 角色的自动转手工与保留原图实测有效。
- 复核表单本身对比度全部达标（133 个文本节点 0 个不合格），主要按钮高度 40-45px。
- admin 专属入口对 owner/staff 隐藏，后端同步 403；业务界面没有出现 JSON/schema/token/canary/RAG 等词（jargon.py 扫描了 staff/owner 全部 Tab）。

## 7. 优先级最高的 5 项修复建议（按投入产出比）

1. **修手机抽屉遮挡（S3-01，S）**：≤640px 时 `#photoSider` 默认隐藏、left 改为 0。改一处 CSS，就能解开手机主流程的阻断。
2. **staff 转手工放权，失败文案按原因区分（S3-02 + S3-04，S）**：允许 staff 转自己上传的单；403/未配置时不报"已转入"；"繁忙"只用于真正的临时错误。满足强制要求里的"逃生通道保留原图"。
3. **算术门禁和结算方式校验口径一致（S3-05，S）**："必须修改"要么真拦，要么改文案加二次确认；创建路径也校验结算方式，后端不默认 credit。避免错单和挂账混进应付。
4. **修对账 NaN 和 `focusFirstIssueField`（S3-06 + S3-20，S）**：两处一行级改动，恢复对账详情和问题定位。
5. **手机端最小可用（S3-03 + S3-08，M）**：加底部 Tab 导航；明细行改成卡片；底部固定全宽"保存并提交"；进入复核后自动滚动到表单；toast 限宽。同时开启 gzip、换小 logo（S3-17），3G 首屏可以从 12.6s 降到预计 3-4s。
