## 4. 实现说明

### 4.1 架构

- 键值层（`demo/static/js/i18n/i18n.js`，全局 `window.I18N`）：`t(key, params, fallback)`、`getLocale()`、`setLocale()`、`onChange()`、`fmtMoney()`（Intl，默认 HKD）、`fmtNumber()`、`fmtDate()`。语言目录在 `locales/zh-Hans.js`、`locales/zh-Hant-HK.js`，共 49 个键：应用标题/品牌/演示横幅、语言切换器、9 个导航项、角色名、通用按钮与提示（保存/取消/确认/删除/上传/审批/刷新/关闭/返回/编辑/搜索/导出/重试/加载中/暂无数据/网络错误/服务器错误）、8 个收据状态名。HTML 支持 `data-i18n` 和 `data-i18n-attr="title:key;data-title:key"`。`main.js` 的 `RECEIPT_STATUSES.label` 和角色切换提示改为经 `i18nLabel()` 取键值；node 沙箱里没有 I18N 时回落原文，现有 harness 不受影响。
- 文字转换层：先按港式用语表做最长匹配切分，用语表词条之间的片段再走 OpenCC（短语最长匹配，至少 2 字，然后单字），最后套香港字形表。前端（i18n.js）和后端（`demo/app/i18n_text.py`）用同一份数据、同一算法，有测试保证两边输出一致。
- DOM 翻译器：只在 `zh-Hant-HK` 下启用。处理文本节点和 `placeholder/title/aria-label/alt/label/aria-*`、按钮型 input 的 `value`、`document.title`，并包装 `alert/confirm/prompt`（prompt 的默认值不转）。跳过 `input`/`textarea` 的值（textarea 只转 placeholder）、`contenteditable`、`script/style/noscript/template`、`[translate="no"]`、`[data-i18n-skip]`。没有 value 属性的 `<option>` 先把原文固化成 value 再改显示文字，避免提交值被改。
- 防死循环：只在结果不同时写回；写回后在同一个回调里 `takeRecords()` 丢掉自己触发的记录；转换器本身是幂等的（构建时补了 87 条「繁体→自身」恒等短语，语料 0 处不幂等），并且记住自己产出过的文本，读回再写入时不会二次转换。
- 首屏：i18n 脚本放在 `<head>`，在 `main.js` 之前同步加载。繁体模式下 `DOMContentLoaded` 前先隐藏 body（最多 300ms），解析期的变动记录直接丢弃，`DOMContentLoaded` 时整页转换一次再显示，之后切到实时模式。按 MutationObserver 回调计时，这一步把首屏开销从 166ms 降到 2.8ms。
- 语言选择：优先级 `?lang=` > `localStorage['app.locale']` > `navigator.languages`（zh-HK/MO/TW/Hant* → 繁体，其余 → 简体）> 简体。切换后整页重载；重载前把当前 Tab 存进 sessionStorage，重载后恢复。URL 带 `lang` 时会同步改写，避免旧参数把选择覆盖回去。en-US 浏览器默认简体，现有测试不受影响。
- 切换器：侧栏角色切换器下方和 evalset 顶栏各一个，两个按钮「简体中文 / 繁體中文」，各自用本语言显示（`translate="no"`，带 `lang` 属性和对应字体），高 38px，原生 button 可键盘操作，有 `aria-pressed`、`aria-label` 和分组 `aria-labelledby`。
- 后端：`ExportReq.lang` 可选；`zh-Hant-HK` 时转换 CSV 表头和文件名，行数据不转（供应商名、品名是业务数据，导出后可能回灌或拿去对账）。`export_center.js` 下载时带上当前语言。

### 4.2 关键取舍

- 识别复核表单的识别值都在 input 里，永不改写；保存回传的是原始数据（e2e 断言了请求体和数据库）。复核表单下拉候选里的供应商名、品名、单位，以及「使用新供应商: "原值"」里的原值，都加了 `data-i18n-skip`，和输入框保持同一字形。
- 展示型表格（库存、流水、归档）里的供应商名、品名会转换显示，不改存储。截图 S5-zh-hant-inventory.png 中「雞蛋麵」对应库里的「鸡蛋面」。这对阅读友好，但老板拿屏幕和纸质单据逐字核对时字形可能不同。
- 短语表按语料裁剪，`zh-hant-data.js` 共 63,317 字节（字符 2715 对、短语 2726 条、香港字形 59 + 17）。代价是语料外的动态文本只能按单字转（例如「头发」会转成「頭發」）。
- 停用 OpenCC HKVariants 的 `戶→户`，并把输出里的「麪」统一替换成「麵」，理由见用语表注释。

## 9. 优先级最高的 5 项后续建议（按投入产出排序）

1. 后端报错改成「错误码 + 参数」，前端用 `t()` 渲染，数据参数放进 `data-i18n-skip` 的 span（I18N-06）。这样能消除句中品名和输入框原值字形不一致的问题，也是将来做英文的前提。
2. 统一金额格式到 `I18N.fmtMoney`（I18N-07）：千分位加统一的 `HK$`，直接降低老板看错位数的风险。
3. 主数据简繁折叠（I18N-08）：分类改代码值，供应商/SKU 匹配和搜索在服务端做简繁归一，避免繁体用户录入产生重复主数据。
4. 原生 confirm/alert 换成自带模态框（I18N-09），按钮文字可控，手机上体验一致。
5. AI 复盘按界面语言出文（I18N-10），并在 CI 加 `python demo/scripts/build_i18n_hant.py --check`，新增文案后提醒重建繁体数据。

## 10. 已知限制

- 转换层只做字形和用语表转换，没有语义理解；语料外的动态文本里，简繁一对多的字可能转错（如「头发」）。可以把高频词补进用语表。
- 夹在提示语里的数据会随提示一起转换（I18N-06）。
- CSV 只转换表头和文件名；行内由后端生成的说明文字（如补货建议）仍是简体。
- 第一次以繁体打开时，body 最多隐藏 300ms。如果 DOMContentLoaded 晚于这个上限，会先显示、再转换，可能短暂看到简体。
- 原生日期控件和原生对话框按钮跟随浏览器语言。
- 不提供英文界面。键值层已支持新增语言目录，步骤见 `docs/i18n.md`；英文需要先把页面文案迁移成键值。
- worktree 里有被 gitignore 的运行时文件：`demo/receipt_demo.db`（导入了 1 张样本，我又在 15021 上加了 2 张测试单、审批了 2 张）、`demo/.rag_chroma/`、`demo/uploads/74849730.jpg`。它们不在 `git status` 中。
- 沙箱没有 `lsof`，demo/tests 的共享服务归属判断会失败，导致 5 个 Playwright 用例报错。可用 `PLAYWRIGHT_REUSE_ANY_SERVER=1` 绕过。
