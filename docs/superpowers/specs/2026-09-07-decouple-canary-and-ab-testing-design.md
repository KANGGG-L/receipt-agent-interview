# 灰度发布 (Canary Release) 与 A/B 测试 (A/B Testing) 彻底解耦设计规格说明书

- **文档状态**: 已对齐草案 (Ready for Review)
- **提出日期**: 2026-09-07
- **方案类型**: 架构与用户界面双端解耦 (方案二)
- **对齐目标**: 将“渐进式验证新版本稳定性并控制风险（灰度）”与“科学对比多种方案的数据优劣以抉择最优解（A/B测试）”在配置端、数据流与观测展示端彻底解耦。

---

## 1. 背景与核心动机

根据软件工程与数据科学的标准定义：
1. **灰度发布（Canary Release / Grayscale Rollout）**：侧重于“渐进式验证新版本稳定性并控制风险”，通过按比例逐步放量（0% -> 10% -> 50% -> 100%），排查未知 Bug，防范大面积系统崩溃，最终闭环为全量推全替换旧版本或紧急一键回滚；
2. **A/B 测试（A/B Testing）**：侧重于“科学对比多种方案的数据优劣以抉择最优解”，通过双盲对等随机分流，对照组 (Control) 与实验组 (Treatment) 并行运行，借助假设检验（双侧双比例 $z$ 检验、效应量 $pp$ 与 $p\text{-value}$）用量化数据决定方案取舍。

系统中原将两者混称为“A/B 分组灰度测试”，并在 `sec-canary` 观测面板中将灰测单据流与 A/B 显著性检验卡片杂糅在同一区域。本方案旨在实现两者的彻底解耦。

## 3. 页面交互与 UI 架构解耦

### 3.1 引擎与系统配置页 (`tab-engine`)
1. **抽屉定位纯粹化**：
   - 抽屉标题由原 `高级配置 · A/B 分组灰度测试` 更新为 **`高级配置 · 金丝雀灰度发布 (Canary Rollout)`**；
   - 彻底剥离任何与 A/B 实验、假设、组别相关的表单，聚焦发布参数：
     - 金丝雀状态开关 (`grey_enabled`)：启用 / 停用；
     - 放量比例 (`grey_percent`)：0 ~ 100% 连续滑块与数字输入；
     - 分流维度 (`grey_assign_mode`)：按单据随机 (`receipt`) / 按供应商哈希 (`supplier`)；
     - 金丝雀版本引擎参数配置（识别模型、审核开关、解析 LLM）；
     - 发布生命周期动作：`配置对比 (Diff)`、`一键推全 (Promote)`、`一键回滚 (Rollback)`。

### 3.2 AI 效果观测与评测中心 (`tab-analytics`)
顶部导航分段控制器由原来的 3 段平级拆分为 **4 个独立且语义清晰的专属功能区**：

```html
<div class="analytics-segmented-nav" role="tablist">
    <!-- 01 埋点与漏斗 -->
    <button class="analytics-segment-btn active" data-view="sec-telemetry">01 埋点分布与挽回</button>
    <!-- 02 金丝雀发布监控 -->
    <button class="analytics-segment-btn" data-view="sec-canary">02 金丝雀发布监控</button>
    <!-- 03 A/B 科学实验台 -->
    <button class="analytics-segment-btn" data-view="sec-experiment">03 A/B 科学实验台</button>
    <!-- 04 基准资产与确权 -->
    <button class="analytics-segment-btn" data-view="sec-eval">04 基准资产与确权</button>
</div>
```

#### 各功能区详细定义：
1. **【01 埋点分布与挽回 (`sec-telemetry`)】**：
   - 保持现有定位：全量埋点事件监控、扫描-录入-复核漏斗、点踩趋势与店员挽回成效。
2. **【02 金丝雀发布监控 (`sec-canary`)】**（专注**稳定性与放量控险**）：
   - **大盘快照卡**：常规主力引擎 vs 金丝雀引擎参数快照、实时分流比例；
   - **稳定性监控栏**：全量样本数、审批入库率、店员纠偏率、异常解析监控；
   - **脱敏单据流实时巡检表**：展示最新 100 条抽样单据（供应商、形态、金额、AI预填效果），支持「查看脱敏解析」；
   - **闭环深链**：右上方常驻「前往推全/回滚操作」按钮，一键直达引擎配置抽屉。
3. **【03 A/B 科学实验台 (`sec-experiment`)】**（专注**科学对照与决策判定**）：
   - **实验大盘卡片**：实验选择下拉框、实验科学假设（Hypothesis）、实验状态（运行中 / 已结题）；
   - **对照组 vs 实验组指标栏**：并列对比 Control 组与 Treatment 组的核心指标（样本量、完全采纳率、人工修正率）；
   - **双侧显著性检验卡片 (Hypothesis Testing)**：双侧双比例 $z$ 检验计算、显著性水平 $\alpha=0.05$ 判定、效应量 (Effect Size pp)；
   - **置信度防护**：样本量 $N < 30$ 时明确标黄提示“低置信度，仅作参考”；当 $N \ge 30$ 且 $p < 0.05$ 且效应量为正时，点亮“实验组具备统计学优势”绿灯；
   - **科学结题操作**：提供实验结题按钮（支持确认采纳实验方案、维持对照组或放弃实验）。
4. **【04 基准资产与确权 (`sec-eval`)】**：
   - 保持现有定位：GT 抽检确权流转入口卡片 + 黄金基准集看板（动态增删改样本）。

## 4. 后端数据模型与 API 路由设计

### 4.1 数据模型隔离
1. **灰度发布配置模型**：
   - 依托 `EngineConfig`（SQLite 存储），持久化金丝雀开关、放量百分比、分流方式及金丝雀备选引擎参数；
   - 支持完整的快照生成与覆盖回滚。
2. **A/B 实验关系模型**：
   - `_ExperimentRow`：存储实验元数据（名称、科学假设、主成功指标、状态、目标放量比例）；
   - `_ExperimentAssignRow`：单据参与实验的分流记录（`grp: 'control' | 'treatment'`）；
   - `_DecisionLogRow`：单据各字段在实验环境下的决策日志。

### 4.2 API 路由职责划分
| 路由端点 | 所属模块 | 功能说明 | 权限要求 |
| :--- | :--- | :--- | :--- |
| `GET /api/admin/grey-test` | 灰度发布 | 获取金丝雀开关状态与主力/灰测引擎快照 | admin / owner |
| `GET /api/admin/grey-test/samples` | 灰度发布 | 获取脱敏单据流实时监控样本及稳定性统计 | admin / owner |
| `GET /api/admin/engine-config/diff` | 灰度发布 | 比对当前主力配置与金丝雀版本参数差异 | admin / owner |
| `POST /api/admin/grey-test/promote` | 灰度发布 | 执行一键推全，将金丝雀参数覆盖为主力 | admin / owner |
| `POST /api/admin/engine-config/rollback` | 灰度发布 | 执行一键回滚，切断灰度流量 | admin / owner |
| `GET /api/admin/experiments` | A/B 实验 | 获取所有 A/B 实验列表与运行状态 | admin / owner |
| `GET /api/admin/experiments/{id}` | A/B 实验 | 获取指定实验的 Control 与 Treatment 对照指标 | admin / owner |
| `GET /api/admin/experiments/{id}/pvalue` | A/B 实验 | 计算双侧 $z$ 检验值、$p\text{-value}$ 与效应量卡片 | admin / owner |
| `POST /api/admin/experiments/{id}/conclude` | A/B 实验 | 结题并归档实验决策结论 | admin / owner |

## 5. 前端交互与并发加载控制

在 `main.js` 中重构分段切换函数 `switchAnalyticsSubView(targetViewId)`：
1. **严格按需加载**：每个分段激活时仅拉取该分段所需的数据，消灭页签初始激活时的跨子面板无序并发；
2. **防陈旧异步序列守卫 (`_analyticsSeq`)**：
   - 为每个加载器配置专属序列标识（`recovery` / `canary` / `experiment` / `goldenBoard`）；
   - 只有请求返回时序列号与最新发起序列号一致时，才允许更新 DOM。

## 6. 验证与回归标准 (Verification Criteria)

1. **功能隔离验证**：
   - 引擎配置抽屉内无任何 A/B 实验混杂文案，推全/回滚操作独立可用；

2. **视觉与排版验证**：
   - 4 个分段按钮样式统一，符合系统整体沉稳墨绿与极简设计规范；
   - 02 区（金丝雀）与 03 区（A/B 实验）各司其职，无横向溢出或单元格截断；
3. **自动化测试**：
   - 保持现有端到端测试 100% 通过（`test_admin_tabs_consolidation_e2e.py`）；
   - 新增解耦专属测试用例，验证 4 分段导航切换与各端点按需加载隔离性。
