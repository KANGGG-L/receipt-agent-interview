## 1. 核心结论与一句话定性

**确定性结论**：SKU 匹配落库标记占比从历史基线 **23.73% (163/687)** 变动为实测 **21.07% (138/655)**，**完全是由于 P0 阶段清退 32 行测试夹具（uat_a / uat_b）导致的分母与结构性偏差，核心 SKU 匹配算法 `_match_sku` 零退化**。

真实匹配算法在当前 655 行数据集上实测复放的 `simulated_match_rate` 达到 **26.26% (172/655)**，叠加别名通道后进一步提升至 **27.63% (181/655)**。

## 3. 被清退 32 行明细深度溯源

对差额明细行进行逆向溯源分析：
1. **清退来源**：P0 治理（W-A / T2 清退阶段）删除了前期人工测试注入的临时单据及夹具（`uat_a`, `uat_b` 及相关脏数据）；
2. **夹具匹配率分布**：
   - 清退总明细行：32 行；
   - 清退明细中 `matched=1` 行数：25 行；
   - 被清退夹具匹配率：$25 / 32 = 78.13\%$。
3. **数学推导验证**：
   - 夹具数据的匹配率（78.13%）畸高，显著高于真实单据基线（21%~23%）；
   - 当将高匹配率的夹具 32 行（分子贡献 25）从全局剔除后：
     $$\text{剩余标记率} = \frac{163 - 25}{687 - 32} = \frac{138}{655} = 21.0687\% \approx 21.07\%$$
   - 理论推导值与实测值 21.07% 逐位吻合。

## 4. 两个口径不可混读说明

- **落库标记占比 (`matched_flag_rate`)**：只统计 `receipt_items.matched=1` 落库标记占总明细行比例（21.07%）。它反映的是历史单据在初次识别或入账时的历史标记残留，受测试数据清洗影响明显；
- **算法匹配成功率 (`simulated_match_rate`)**：通过 `backfill_vendor_sku_alias.py --replay` 在同一批明细上重新运行当前核心算法 `_match_sku`（含核心词归一与别名），实测达到 26.26%（172/655）。

**纪律声明**：两口径不可混读、不可相互比较，后续监控与汇报统一采用两口径分列与交叉引用自述。
