# 界面国际化（简体中文 / 繁體中文（香港））

## 架构

前端是纯静态页面（无构建步骤），i18n 分两层，全部在 `demo/static/js/i18n/`：

| 文件 | 作用 |
| --- | --- |
| `i18n.js` | 核心：`window.I18N`（`t` / `getLocale` / `setLocale` / `onChange` / `fmtMoney` / `fmtNumber` / `fmtDate`）、文字转换器、DOM 翻译器、语言切换器 |
| `locales/zh-Hans.js` | 简体（源语言）键值目录 |
| `locales/zh-Hant-HK.js` | 繁体（香港）键值目录，人工校对 |
| `zh-hant-hk-glossary.js` | 港式用语表（人工维护，优先级高于 OpenCC） |
| `zh-hant-data.js` | OpenCC s2hk 字典裁剪结果（脚本生成，勿手改） |
| `demo/app/i18n_text.py` | 同一算法的 Python 实现，供 CSV 导出等不经过浏览器 DOM 的输出使用 |

1. 键值层：`I18N.t('nav.inventory')`。HTML 中可声明式绑定：`data-i18n="key"`（替换文字）、
   `data-i18n-attr="title:key;placeholder:key"`（替换属性，可绑定任意属性，如 `data-title`）。
   用于导航、页面标题、语言/角色切换器、通用按钮、收据状态名、通用提示。缺少繁体键时回落到简体原文再经转换层转换。
2. 文字转换层：语言为 `zh-Hant-HK` 时，DOM 翻译器把页面文本节点与提示属性
   （`placeholder` `title` `aria-label` `alt` `label` 等、按钮型 input 的 `value`）转换为繁体，
   并用 MutationObserver 处理之后由 `main.js` 动态渲染的内容、后端返回并显示的提示；
   `alert/confirm/prompt` 的提示语与打印窗口也会转换。转换顺序：港式用语表最长匹配切分，
   用语表之间的片段走 OpenCC（短语 > 单字），再套香港字形表。转换器带缓存且幂等。

转换层永远不碰：`input`/`textarea` 的值、`contenteditable`、`script`/`style`、
带 `translate="no"` 或 `data-i18n-skip` 的子树。识别复核表单的识别值都在 input 里，保存回传的是原始数据。
业务身份数据（导出中心预览的品名/供应商/部门名、成本明细品名、复核下拉候选等）须加
`data-i18n-skip`，与 CSV/DB/输入框原值逐字一致；UI chrome 与表头仍走转换层，禁止全局关闭繁体。

语言优先级：URL `?lang=` > `localStorage['app.locale']` > `navigator.languages`
（zh-HK / zh-MO / zh-TW / zh-Hant* → 繁体，其他 → 简体）> 简体。`<html lang>` 随语言设为
`zh-Hans` / `zh-Hant-HK`，`style.css` 用 `:lang()` 选对应 CJK 字体。切换语言会整页重载，
重载前把当前 Tab 记在 sessionStorage，重载后恢复。

## 新增文案

- 外壳与新代码：在 `locales/zh-Hans.js` 加键，再在 `locales/zh-Hant-HK.js` 加人工校对的译文；
  HTML 用 `data-i18n`，JS 用 `I18N.t(key, params)`（`main.js` 内可用 `i18nLabel(key, fallback)`，
  在 node 沙箱等无 i18n 环境下回落原文）。
- 其余直接写简体即可，繁体界面由转换层覆盖。若某个词的港式说法与 OpenCC 结果不同，
  加到 `zh-hant-hk-glossary.js`（`s` 简体原文，`t` 最终显示文本，有争议写 `note`），然后重建数据。
- 显示业务原始数据（需要与单据逐字核对）的元素加 `data-i18n-skip`。

## 重建繁体数据

```
source /home/user/.venvs/receipt/bin/activate
python demo/scripts/build_i18n_hant.py          # 重新生成 zh-hant-data.js
python demo/scripts/build_i18n_hant.py --check  # 只校验是否最新
```

需要 `opencc-python-reimplemented`（仅构建期依赖，运行时不需要）。短语表只保留本项目语料
（templates、static/js、demo/app、样本 JSON）中出现过的短语，输出排序稳定。脚本还会补「繁体 → 自身」
的恒等短语保证幂等，并校验用语表译文二次转换不变。改了用语表或大量新增文案后需要重建。

## 新增语言（如英文）

1. 新建 `locales/en.js`，写入 `(root.I18N_LOCALES = root.I18N_LOCALES || {})['en'] = {...}`，并在两个模板中引用；
2. 在 `i18n.js` 的 `SUPPORTED`、`HTML_LANG`、`NATIVE_NAMES`、`INTL_LOCALE` 与 `normalizeLocale` 中登记；
3. 英文不启用文字转换层，只有键值层覆盖的文案会变成英文，因此必须先把页面文案迁移成键值，
   才适合对外提供英文界面。

## 已知限制

- 转换层按「字形 + 用语表」转换，没有语义理解；不在语料中的短语按单字转换，
  动态数据里偶有简繁一对多的字可能转错（如「头发」）。
- 夹在提示语里的数据（如「第 1 行『鸡蛋面』单价…」）会随提示一起转换，与输入框中的原值字形可能不同。
- CSV 导出只转换表头与文件名；行内由后端生成的文字（如补货建议）仍为简体。
- 首次以繁体打开时，DOMContentLoaded 前页面短暂隐藏（最多 300ms）。
- 原生控件（日期选择器）跟随浏览器语言，不受本机制控制。
