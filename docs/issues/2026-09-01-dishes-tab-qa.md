## BUG-002 存储型 XSS：单位字段经卡片视图注入（高）

**复现**：餐品 BOM 配方库 → + 新建餐品 → 配方行单位输入 `<b>X</b>` → 保存 → 卡片视图配方摘要中 `<b>` 被浏览器当 HTML 渲染（实测徽章文本变为 `商品A: 1X`，`<b>` 生效）。

**根因**：`renderDishCards` 拼接配方摘要时 `ing.consumption_qty + ing.unit` 未经 `w2Escape`（main.js:13543）；单位是自由文本输入，前端仅校验非空，后端仅 `.strip()`。

**对照**：列表视图同内容走了 `w2Escape(ingSummary)`（main.js:13620）；每日录入表配方简述同样已转义（main.js:14217）。仅卡片视图遗漏。

**修复建议**：对 `ing.consumption_qty + ing.unit` 整体 `w2Escape`。

## BUG-003 「其他」分类删除死角（中）

**复现**：管理分类 → 删除「其他」→ 确认弹窗文案自相矛盾（「删除分类『其他』？……这些餐品的分类将改为『其他』」）→ 确认后报错 toast「替代分类不能与删除分类相同」。

**根因**：前端 `deleteDishCategory` 固定走默认 `replace_with=其他`（main.js:13460），未提供替代分类选择；后端校验 `replace == cat` 直接 400（api_dishes.py:477）。「其他」分类因此永远删不掉。

**修复建议**（任选其一）：
1. 删除弹窗增加「替代分类」输入（默认值避开被删分类）；
2. 后端对被删分类恰为替代默认值时自动降级为空字符串（即清空归类）；
3. 最低成本：前端对名为「其他」的分类隐藏删除按钮并加说明。
另建议把错误文案从技术黑话改为人话（对齐 D-8 文案标准）。

## BUG-001 KPI 标签与值单位不一致 + 笔数口径含冲销（低）

**复现**：每日消耗录入页第 4 张 KPI 卡，标签为「已录入消耗餐品」（静态初始值「0 种」），加载后值变成「0 笔流水」（main.js:14185 写 `records_count + ' 笔流水'`）。冲销全部流水后成本/营业额归零，但笔数仍为「3 笔流水」（records_count 含已冲销，而金额口径排除已冲销）。

**修复建议**：标签改为「当日消耗流水笔数」，或改用 `records_count - void_count` 并保留「有效流水」口径。

## BUG-004 「预估」KPI 不随输入联动（低）

**复现**：在极速录入表输入份数（步进/直输），「当日预估总成本 (BOM)」「当日预计营业额」「当日预估毛利率」保持 ¥0 不动；只有提交后才显示实际值。标签「预估」+ 徽章「基准理论」暗示应随输入实时估算。

**修复建议**：输入时按 `Σ 份数 × (理论成本/售价)` 实时更新预估，提交后切换为实际值；或把标签改为「当日已核算实际成本」避免误导。

## BUG-006 分类管理弹窗顶部说明文案与实际行为不符（低，第二轮发现）

**复现**：餐品 BOM 配方库 → 管理分类 → 弹窗顶部固定显示「删除分类后，引用该分类的餐品将自动改为『其他』。」；但 BUG-003 修复后，删除「其他」本身的行为是**清空分类**（`replace_with` 传空），不再是「改为其他」。

## BUG-007 已有提交流水时第 1 卡徽章仍为「基准理论」（低，第二轮发现）

**复现**：切到已有提交流水的日期（实测种子数据日 2026-08-27）：第 1 卡值为实际 FIFO 成本 ¥240.00，但徽章仍显示「基准理论」（badge-warning）；徽章声称的口径（理论基准）与值的实际口径（FIFO 实际成本）脱节。无流水无输入时显示 ¥0.00 +「基准理论」则无歧义。

**根因**：BUG-004 修复引入的 `refreshDishKpiEstimates` 只在「有未提交输入」时把徽章切为「预估叠加 N 份未提交」，其余情况一律回落「基准理论」，未区分「已提交流水的实际值」。

**修复建议**：无未提交输入但当日有有效流水时，徽章改「实际 FIFO」（badge-success 或 badge-info）；卡片标签中的「预估」二字同样建议按值口径动态化（实际/预估）。
