#  香港餐饮 AI 进货决策系统：前端交互升级与品类治理开发方案

## 一、项目背景与核心目标 (Problem Statement & Goals)
在香港餐饮场景中，后厨店员与财务在单据录入与品类管理中面临两大深水区痛点：
1. **SKU 治理与自学习缺失**：
   - 无法在录单时内联新建 SKU，导致新食材无法纳入库存与成本核算；
   - 无法对误建、重复建立的 SKU 进行删除或合并；
   - 无法对不同供应商的不同别称（如“菜心苗”与“特级菜芯”）进行同义合并并沉淀为 LLM 正向记忆。
2. **手写单据混写剥离痛点**：
   - 香港 NCR 单据常在品名中混写数量与单位（如“菜心 20斤”、“大豆油 5L*2樽”），OCR 将其识别为单一品名且数量默认为 1，导致单价与库存核算失真。

## 二、详细开发方案 (Development Specification)

### 1. 后端 API 扩展
- **`POST /api/inventory/skus/merge`** (SKU 合并)：
  - 参数：`primary_sku_id: int`, `secondary_sku_ids: list[int]`
  - 逻辑：将副 SKU 的历史进货日志（`inventory_log`）外键迁移至主 SKU；将副 SKU 标记停用（`active = 0`）；将副 SKU 名称写入主 SKU 的供应商别名映射库（`vendor_memory`），实现自学习。
- **`DELETE /api/inventory/skus/{sku_id}`** (SKU 安全删除/停用)：
  - 逻辑：若无历史进货流水，执行物理删除；若存在历史流水，执行软停用（`active = 0`），返回友好提示。

### 2. 前端交互升级 (`demo/static/js/main.js` & `demo/templates/index.html`)
- **功能 A：明细行「内联快捷新建 SKU」**
  - 在品名/SKU 下拉搜索中增加常驻条目：`+ 为当前品名新建 SKU「xxx」`；
  - 弹出极简 Modal，支持品名、基础单位、品类、警戒线；
  - 提交后乐观更新（Optimistic UI），当前行自动绑定新 SKU，无需跳页。
- **功能 B：明细行 SKU 重绑、解绑与供应商别名记忆自学习**
  - 明细行已绑定的 SKU 支持一键清除/更换；
  - 调整绑定后，自动更新供应商对于该品名的正向记忆（`VendorMemory`）。
- **功能 C：品名-数量-单位智能剥离引擎 (Smart Splitter)**
  - 内置确定性正则与规则解析器（识别 `\d+(\.\d+)?\s*(斤|两|公斤|kg|g|磅|箱|包|罐|樽|盒|条|隻|袋)` 及乘法规格 `5L*2`）；
  - 渲染明细表时自动执行预清洗；
  - 行内提供小魔棒  按钮，点击可即时分离数量、单位并自动重算单价 `unit_price = amount / quantity`。
- **功能 D：库存中心 SKU 合并与停用治理**
  - 「实时库存与价格」页面支持勾选多个 SKU 进行合并操作。

## 三、检验方案 (Test & Verification Plan)

### 1. 单元与接口测试 (API Contract Tests)
- `test_sku_inline_create`: 验证新建 SKU 成功，参数校验与防重名；
- `test_sku_merge_and_history_migration`: 验证合并主副 SKU 后，历史流水是否迁移，副 SKU 是否停用，别名是否沉淀到 `VendorMemory`；
- `test_sku_safe_deletion`: 验证无流水物理删除 vs 有流水软停用。

### 2. 前端智能剥离算法测试 (Smart Splitter Unit Tests)
- 用例 1: `菜心 20斤` -> Name: `菜心`, Qty: `20.0`, Unit: `斤`；
- 用例 2: `大豆油 5L*2樽` -> Name: `大豆油 5L`, Qty: `2.0`, Unit: `樽`；
- 用例 3: `特级白菜 2.5公斤` -> Name: `特级白菜`, Qty: `2.5`, Unit: `公斤`；
- 用例 4: `纯净品名无数量` -> 保持原样不误伤。

### 3. 端到端角色旅程验证 (E2E Persona Simulation)
- 后厨阿强旅程：上传单据 -> 发现品名混写 -> 智能剥离 -> 快捷新建 SKU -> 保存成功；
- 财务May姐旅程：进入库存中心 -> 发现重复 SKU -> 一键合并 -> 检查历史加权成本完整性。

## 四、预期交付成果 (Expected Outcome)

1. **核心痛点 100% 消除**：
   - 彻底解决“无法自定义/新建 SKU”以及“无法合并/删除 SKU”的问题；
   - 手写单据数量混写提取准确率达 95% 以上，单价计算失真率降低 90%。
2. **零破坏性与向下兼容**：
   - 历史进货单据与对账报表数据 100% 保真，无破损外键；
   - 全程支持键盘操作与即时 Toast 提示。
3. **闭环资产沉淀**：
   - 完备的自动化测试用例集；
   - 验收报告与四角色审查纪要归档至 `docs/`。
