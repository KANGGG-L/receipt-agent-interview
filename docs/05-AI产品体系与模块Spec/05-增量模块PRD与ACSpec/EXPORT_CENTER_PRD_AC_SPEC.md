- 文档版本：v1.0.0
- 负责角色：产品规格子代理 (Product / Spec Subagent)
- 生效系统：香港餐饮数字化收据与进销存管理系统 (Receipt Agent & F&B Operations)
- 关联模块：实时库存与价格 (Inventory)、餐品与消耗 (Dishes)、供应商与归档 (Suppliers & Receipts)、部门花销报表 (Department)

- 实施状态：[APPROVED-FOR-IMPLEMENTATION]

## 1. 需求背景与核心用户画像

### 1.1 业务背景
餐饮进销存系统在经过单据识别、批次建档、BOM 消耗扣减和部门分摊后，沉淀了大量的核心经营流水。然而，传统表格导出分散在各二级页面中，存在格式不统一、Excel 打开中文乱码、字段口径不一、前线员工操作门槛过高等系统性问题。「统一报表与数据导出中心 (Export & Reporting Center)」旨在建立统一的报表枢纽，提供涵盖四大业务域的 14 套标准数据报表，实现“实时在线预览、一键安全脱敏、UTF-8 BOM 防乱码导出、A4 实地盘点打印”一体化交付。

### 1.2 核心用户画像与高压环境痛点

#### 1.2.1 老华侨餐厅老板 (Owner / Director)
- 核心诉求：
  - 月末全局掌控食材总货值、部门花销环比、菜品真实毛利与被侵蚀点。
  - 导出报表直接在 Mac Numbers 或 Windows Excel 中双击打开，绝不允许出现中文乱码或符号错位。
  - 商业机密与供应商私人联系方式保护，对外报送数据必须一键脱敏。
- 关键痛点场景：
  - 过去导出的 CSV 在 Excel 中显示为乱码（缺乏 UTF-8 BOM）；
  - 报表总额与流水总额存在尾差，无法用于向股东汇报；
  - 担心店员将带有进货底牌与供应商老板私人生意电话的数据私自导出外泄。

#### 1.2.2 库管阿叔 (Kitchen / Storekeeper Uncle)
- 核心诉求：
  - 每周/月末进冷库或干货仓现场点货，需要一键生成并打印标准纸质《实时库存盘点底单》。
  - 盘点单必须有宽敞的留白列供现场圆珠笔手填实际数量、盘盈盘亏差异及签名确认。
- 关键痛点场景：
  - 未受过高等电脑教育，视力存在老花，屏幕字号过小或浅灰色看不清；
  - 冷库温度极低且嘈杂高压，无法在手机或电脑上做复杂的多级筛选或拖拽；
  - 需要系统提供大号字、大按钮、傻瓜式操作，一键直达“打印底单”。

#### 1.2.3 财务出纳 (Accountant / Cashier)
- 核心诉求：
  - 严谨的排款做账台账：逐行穿透到单据每一行明细（品名、单价、数量、金额、税费、归属部门）。
  - 供应商账期逾期监控（账龄分析）与对账差异核销（系统单据 vs 外部对账单）。
  - 数值精度必须达到分钱级（保留 2 位小数），各表加总必须保持代数恒等。
- 关键痛点场景：
  - 过去单据抬头与明细分离，出纳需在两个表格间 VLOOKUP 匹配，耗时极长且容易错行；
  - 供应商来催款时无法快速拉出未付赊单及账龄，导致对账扯皮。

#### 1.2.4 香港餐饮前线店员 (Staff - 阿叔/阿姨)
- 核心诉求：
  - 协助前台与后厨调取当天出入库记录或补打收据流水。
  - 界面操作零学习成本，杜绝任何技术黑话或生硬英文报错。
- 关键痛点场景：
  - 高压备料或收市期间手上有油水，触控靶区如果小于 38px 极易误触相邻按钮；
  - 一旦误选日期（如结束日期早于开始日期），系统直接报错“Invalid Date Range”或界面白屏，阿叔阿姨完全不知所措；
  - 遇到系统算术拦截时，只有英文代号或冷冰冰的“校验失败”，不知道到底差了多少钱。

## 2. 系统架构与设计准则

### 2.1 整体架构设计
数据导出中心采用“元数据驱动 + 统一数据管道 + 实时抽样预览 + 流式生成下载”架构：
1. **元数据引擎 (`GET /api/export/reports`)**：解耦前端展示与报表定义，报表分类、字段规范、支持的过滤器均由元数据下发。
2. **数据处理管道 (`ExportDataProcessor`)**：统一多租户安全上下文注入，统一执行敏感字段掩码脱敏，统一格式化数值精度。
3. **实时预览引擎 (`POST /api/export/preview`)**：轻量级内存切片（最多返回前 15 行），附带大盘关键指标汇总胶囊（Summary Pills），减少前端渲染开销。
4. **流式导出引擎 (`POST /api/export/download`)**：写入标准 UTF-8 BOM (`\ufeff`)，CSV 字段强制遵循 RFC 4180 转义规范，响应头使用 RFC 5987 对中文文件名进行 URL 编码，杜绝下载乱码。

### 2.2 无障碍与香港餐饮场景高压人机工程学准则
- **[UX-1] 按钮触控靶区底线**：所有主要按钮（导出、打印、刷新、分类切换）高度均不得小于 38px，点击热区内边距满足触控标准。
- **[UX-2] 对比度符合 WCAG AA**：前景色与背景色对比度严格达到 4.5:1 以上，文字禁止使用低对比度淡灰色（如 `#cbd5e1` 配白底），主操作使用高饱和度辨识色彩。
- **[UX-3] 100% 直白人话文案**：杜绝出现任何技术术语（严禁出现 "HTTP 400", "NaN", "Null", "SyntaxError", "SQL", "Schema"）。所有提示与报错必须使用平实人话，并明确给出下一步操作指引。
- **[UX-4] 容错与自动防呆**：日期选择发生逻辑倒置时，禁止向用户抛出异常红字，系统必须自动对齐或智能对调，并展示温和的人话提示。
- **[UX-5] 物理打印与现场留白标准**：支持一键调用浏览器打印，盘点类表格必须包含实盘手填留白列与三级签字确认栏（经办人、主管、日期）。

## 3. 四大业务域 14 套标准报表业务规格定义

### 3.1 模块一：实时库存与价格 (Inventory & Pricing)

#### 报表 1：实时库存盘点底单
- 报表 ID：`inventory_stocktake`
- 业务定位：供库管阿叔与后厨现场打印带入冷库/仓库，逐项核对实物并手填记录。
- 数据来源：`skus` 活跃表、`inventory_log`
- 支持筛选：食材分类 (`category`)、库存状态 (`stock_filter: all/low`)
- 默认排序：分类升序，食材品名升序
- 表头字段清单：
  1. `食材代码` (文本, 如 SKU-101)
  2. `食材品名` (文本, 如 鲜活海虾)
  3. `分类` (文本, 如 海鲜)
  4. `基本单位` (文本, 如 斤/kg)
  5. `系统账面库存` (数值, 2位小数, 如 25.50)
  6. `安全警戒线` (数值, 2位小数, 如 10.00)
  7. `实盘数量(现场手填)` (留空白列，打印供手写)
  8. `盘盈/盘亏差异` (留空白列，打印供手写)
  9. `盘点人员签字` (留空白列，打印供手签)
  10. `备注` (文本, 低库存时显示“低库存预警”)
- 汇总指标 (Summary)：总品类数、盘点基准日期
- 空状态文案：“未找到需要盘点的食材，请检查分类筛选设置。”

#### 报表 2：食材库存结存与货值统计表
- 报表 ID：`inventory_valuation`
- 业务定位：老板与财务评估餐厅即时流动资产总额，排查高货值滞销与断料风险。
- 数据来源：`skus`、批次最新入库价
- 支持筛选：食材分类 (`category`)、库存状态 (`stock_filter: all/low`)
- 默认排序：库存货值降序
- 表头字段清单：
  1. `食材代码` (文本)
  2. `食材品名` (文本)
  3. `分类` (文本)
  4. `基本单位` (文本)
  5. `当前库存` (数值, 2位小数)
  6. `折算标准kg` (数值, 2位小数，非质量单位显示“-”)
  7. `最新进货单价(元)` (金额, 2位小数)
  8. `库存货值估算(元)` (金额, 2位小数, 公式: 当前库存 * 最新进价)
  9. `安全警戒线` (数值, 2位小数)
  10. `库存状态` (文本, 正常 / [低库存])
- 汇总指标 (Summary)：统计SKU种数、估算总货值(元)、标准重量合计(kg)
- 空状态文案：“暂无食材结存记录，请先在库存模块添加物料档案。”

#### 报表 3：采购进价波动与比价分析表
- 报表 ID：`inventory_price_anomaly`
- 业务定位：采购议价与控本核心工具，标红涨幅异常食材，识别供货商涨价侵蚀。
- 数据来源：`skus`、`price_history`、近 30 天采购入库均价
- 支持筛选：食材分类 (`category`)
- 默认排序：波动幅度绝对值降序
- 表头字段清单：
  1. `食材品名` (文本)
  2. `食材代码` (文本)
  3. `分类` (文本)
  4. `基本单位` (文本)
  5. `最新进价(元)` (金额, 2位小数)
  6. `近30天均价(元)` (金额, 2位小数)
  7. `波动幅度` (百分比, 如 +15.2% / -3.1%)
  8. `价格异动预警` (文本, 正常 / [涨价异动])
  9. `历史最低价(元)` (金额, 2位小数)
  10. `历史最高价(元)` (金额, 2位小数)
- 汇总指标 (Summary)：分析SKU总数、涨价预警SKU数
- 空状态文案：“所选分类下食材进价稳定，无历史波动记录。”

#### 报表 4：出入库全量流水综合台账
- 报表 ID：`inventory_stock_logs`
- 业务定位：审计物理库存所有变动轨迹（采购入库、销售扣减、后厨报损、盘点调整）。
- 数据来源：`inventory_log`
- 支持筛选：业务日期范围 (`start_date`, `end_date`)、变动类型 (`log_kind: in/consume/waste/stocktake`)
- 默认排序：业务时间倒序 (`id DESC`)
- 表头字段清单：
  1. `流水编号` (文本, 如 LOG-1024)
  2. `业务日期` (日期, YYYY-MM-DD)
  3. `业务类型` (文本, 采购入库/餐品消耗/后厨报损/盘点调整)
  4. `食材品名` (文本)
  5. `变动数量` (数值, 2位小数)
  6. `单位` (文本)
  7. `变动金额(元)` (金额, 2位小数)
  8. `往来供应商/经手` (文本, 支持脱敏)
  9. `关联单据号` (文本, 如 #128 或 -)
  10. `操作备注` (文本)
- 汇总指标 (Summary)：流水总笔数、总变动金额合计(元)
- 空状态文案：“所选日期范围内无任何出入库流水记录。”

### 3.2 模块二：餐品与消耗 (Dishes & Consumption)

#### 报表 5：餐品 BOM 标准配方明细表
- 报表 ID：`dish_bom_recipes`
- 业务定位：后厨标准化出品与单品理论成本档案，明确每道菜的原料消耗配比。
- 数据来源：`dishes`、`dish_ingredients`、`skus`
- 支持筛选：餐品状态 (`dish_status: active/inactive/all`)、餐品分类 (`dish_category`)
- 默认排序：餐品分类升序，餐品名称升序
- 表头字段清单：
  1. `餐品名称` (文本, 合并项首行展示)
  2. `餐品分类` (文本)
  3. `在售标价(元)` (金额, 2位小数)
  4. `配方食材` (文本)
  5. `单份用量` (数值, 3位小数)
  6. `用量单位` (文本)
  7. `食材进价(元)` (金额, 2位小数)
  8. `单项成本(元)` (金额, 2位小数)
  9. `理论整单成本(元)` (金额, 2位小数)
  10. `理论毛利率(%)` (百分比, 如 68.5%)
  11. `状态` (文本, 在售 / 停用)
- 汇总指标 (Summary)：餐品种数
- 空状态文案：“未找到匹配的餐品配方，请在餐品管理中完善 BOM 档案。”

#### 报表 6：每日销售与食材实际成本汇总表
- 报表 ID：`dish_daily_sales_cost`
- 业务定位：前台售卖份数与 FIFO 先进先出扣减的真实食材成本对齐，核算日度实际毛利。
- 数据来源：`daily_consumption`、`dishes`、`inventory_batches`
- 支持筛选：核算日期范围 (`start_date`, `end_date`)
- 默认排序：核算日期倒序，单据 ID 倒序
- 表头字段清单：
  1. `核算日期` (日期, YYYY-MM-DD)
  2. `餐品名称` (文本)
  3. `售出份数` (数值, 1位小数, 支持半份如 0.5)
  4. `单份售价(元)` (金额, 2位小数)
  5. `营业总额(元)` (金额, 2位小数, 份数 * 售价)
  6. `FIFO实际食材成本(元)` (金额, 2位小数)
  7. `实际毛利额(元)` (金额, 2位小数, 营业总额 - 实际成本)
  8. `实际毛利率(%)` (百分比, 1位小数)
  9. `理论基准成本(元)` (金额, 2位小数)
  10. `成本偏差(元)` (金额, 2位小数, 实际成本 - 理论成本)
  11. `状态` (文本, 已核销 / 已冲销作废)
- 汇总指标 (Summary)：总销售额(元)、实际食材总成本(元)、综合毛利率
- 空状态文案：“所选日期区间内未录入餐品销售消耗记录。”

#### 报表 7：餐品理论毛利 vs 真实毛利偏差诊断表
- 报表 ID：`dish_margin_variance`
- 业务定位：识别因食材采购涨价对菜品毛利的实际侵蚀，辅助老板制定调价策略。
- 数据来源：`dishes`、`daily_consumption` 周期加权
- 支持筛选：核算日期范围 (`start_date`, `end_date`)
- 默认排序：毛利侵蚀点降序
- 表头字段清单：
  1. `餐品名称` (文本)
  2. `分类` (文本)
  3. `在售标价(元)` (金额, 2位小数)
  4. `理论成本(元)` (金额, 2位小数)
  5. `理论毛利率(%)` (百分比, 1位小数)
  6. `加权实际成本(元)` (金额, 2位小数)
  7. `实际综合毛利率(%)` (百分比, 1位小数)
  8. `成本溢价额(元)` (金额, 2位小数, 符号化如 +3.50)
  9. `毛利侵蚀点(%)` (百分比, 1位小数)
  10. `诊断分析建议` (文本, 稳定 / 进货价微涨 / [预警] 成本大幅承压)
- 汇总指标 (Summary)：分析在售餐品数
- 空状态文案：“统计周期内暂无餐品售出消耗数据，无法进行毛利偏差对比。”

#### 报表 8：后厨食材累计消耗总量与采购建议
- 报表 ID：`dish_ingredient_consumption`
- 业务定位：后厨阶段性原料消耗盘点，自动结合当前库存与安全库存输出补货采购建议。
- 数据来源：`inventory_log` (consume + waste)、`skus`
- 支持筛选：统计日期范围 (`start_date`, `end_date`)、食材分类 (`category`)
- 默认排序：累计消耗成本降序
- 表头字段清单：
  1. `食材品名` (文本)
  2. `分类` (文本)
  3. `单位` (文本)
  4. `周期累计消耗量` (数值, 2位小数)
  5. `当前系统库存` (数值, 2位小数)
  6. `安全库存线` (数值, 2位小数)
  7. `累计消耗成本(元)` (金额, 2位小数)
  8. `建议采购补货量` (文本, 如“15.0 斤”或“库存充足”)
- 汇总指标 (Summary)：消耗食材种数
- 空状态文案：“所选日期范围内无食材消耗记录。”

### 3.3 模块三：供应商与归档 (Suppliers & Receipts)

#### 报表 9：采购收据入账全量明细台账 (含行项目)

- 数据来源：`receipts`、`receipt_items`、`suppliers`、`departments`
- 支持筛选：开单日期范围 (`start_date`, `end_date`)、单据状态 (`receipt_status`)、指定供应商 (`supplier_id`)、归属部门 (`department_id`)
- 默认排序：开单日期倒序，单据 ID 倒序
- 表头字段清单：
  1. `收据ID` (文本, 如 #88)
  2. `开单日期` (日期, YYYY-MM-DD)
  3. `供应商名称` (文本, 支持脱敏)
  4. `供应商电话` (文本, 支持脱敏)
  5. `单据总额(元)` (金额, 2位小数)
  6. `单据状态` (文本, 已入账/待核对/已修改/有问题/失败)
  7. `付款状态` (文本, 已付/未付)
  8. `归属部门` (文本, 如 后厨/点心房/水吧/楼面)
  9. `商品品名` (文本, 支持脱敏)
  10. `采购数量` (数值, 2位小数)
  11. `单位` (文本)
  12. `单价(元)` (金额, 2位小数)
  13. `行金额(元)` (金额, 2位小数)
- 汇总指标 (Summary)：总记录行数
- 空状态文案：“未找到匹配条件的采购收据及明细记录。”

#### 报表 10：供应商应付账款与账期逾期表
- 报表 ID：`supplier_payables_aging`

## 4. 关键交互流程与边界异常场景 (Edge Cases)

### 4.1 核心交互流程
1. **分类与报表选择**：
   - 用户点击顶部“业务域分类 Tab”（全部报表、实时库存与价格、餐品与消耗、供应商与归档、部门花销报表），左侧卡片列表联动过滤。
   - 用户可点击“快捷场景预置卡”（如月末财务结账归档包、后厨冷库现场盘点底单、餐品毛利与成本偏差大盘），系统自动定位分类、切换目标报表并载入推荐时间区间。
2. **过滤参数联动与即时预览**：
   - 右侧工作区动态加载当前报表专属的筛选控件（日期、供应商、部门、状态等）；
   - 用户变更任何过滤项，前端以 200ms 防抖自动触发 `POST /api/export/preview` 刷新；
   - 预览区域展示前 15 条抽样行与指标汇总胶囊；表格金额列右对齐，状态标签高对比度上色。
3. **安全下载与格式保障**：
   - 用户点击“导出 CSV (Excel)”按钮，触发 `POST /api/export/download`；
   - 浏览器自动接收带 UTF-8 BOM 的 CSV 附件流，并保存为带有规范日期时间的文件名。

### 4.2 边界异常场景与防呆兜底设计

| 异常编号 | 异常场景定义 | 传统缺陷 / 风险表现 | 本规范防呆与兜底设计标准 |
|---|---|---|---|
| EC-1 | 日期倒置（开始日期 > 结束日期） | 请求后端报错 400 或返回空列表，店员面对生硬报错不知所措 | **前端自动纠偏**：触发日期变动时，系统检测到开始日期晚于结束日期，自动将两端日期互换对调，并弹窗人话提示：“检测到日期前后颠倒，已自动为您纠正为正确顺序”，杜绝阻断。 |
| EC-2 | 空数据导出（0 匹配行） | 导出仅有一行表头的空文件，或前端直接白屏崩溃 | **防呆拦截提示**：当总记录数为 0 时，点击导出按钮弹出友好对话框：“当前筛选条件下没有数据，请重新选择日期或分类后再试”，避免生成无意义垃圾文件。 |
| EC-3 | CSV 注入攻击 (Formula Injection) | 恶意供应商名称或品名以 `=`, `+`, `-`, `@` 开头，Excel 打开触发公式执行恶意代码 | **公式前缀安全转义**：后端 CSV 序列化器检测到文本首字符为 `=`, `+`, `-`, `@`, `\t`, `\r` 时，自动在首位补充前导半角单引号 `'`，强制 Excel 将其作为纯文本渲染。 |
| EC-4 | 字段包含特殊符号（逗号、双引号、换行） | 导出的 CSV 列错位，双引号截断导致整表损毁 | **严格遵循 RFC 4180**：所有包含逗号、换行符、双引号的字段值必须使用标准双引号包裹，字段内的原生双引号转义为双重双引号 `""`。 |
| EC-5 | 脱敏模式明文/脱敏切换一致性 | 勾选脱敏后在线预览已脱敏，但下载的 CSV 仍泄露明文 | **管道级脱敏同步**：脱敏参数 `desensitized: true` 作为强制契约注入 `ExportDataProcessor`，无论是在线预览前 15 行，还是全量下载生成的 CSV，脱敏掩码逻辑 100% 保持严格一致。 |
| EC-6 | 零除与缺失值容错 (Divide by Zero) | 菜品销量为 0 或营业额为 0 时计算毛利率触发 `ZeroDivisionError` 崩溃 500 | **代数防御兜底**：毛利率公式必须严格执行防御判断，营业额为 0 时统一安全返回 `0.0%`；食材暂无采购价时标示为待确认，禁止服务端抛出 500。 |
| EC-7 | 多租户越权穿透 | 租户 A 在下拉框中传入租户 B 的供应商 ID，导出跨租户收据 | **强制会话级租户范围锁**：所有数据库查询必须经过 `db.scoped(query, Model, tenant_id)` 严格约束，任何不属于当前租户的过滤参数一律强制静默剔除或返回 403。 |
| EC-8 | 极端大数据量超时与大批量流水响应 | 导出数万条流水导致服务端阻塞与内存溢出 | **流式生成与响应缓冲**：后端必须使用 `StreamingResponse` 配合行生成器分块输出，禁止在内存中一次性分配超大字符串，保障 5000 行级导出响应时间在 1.5 秒内。 |

## 5. 严格量化验收准则清单 (Acceptance Criteria, AC-1 至 AC-12)

### [AC-1] 四大业务域 14 套标准报表元数据契约与定义完备性
- **GIVEN** 系统正常启动，前端发起 `GET /api/export/reports` 请求；
- **WHEN** 服务端返回报表定义清单；
- **THEN** 系统必须返回 HTTP 200，且 `data` 数组长度严格等于 14：
  - 属于 `inventory` 业务域的报表严格为 4 个（`inventory_stocktake`, `inventory_valuation`, `inventory_price_anomaly`, `inventory_stock_logs`）；
  - 属于 `dishes` 业务域的报表严格为 4 个（`dish_bom_recipes`, `dish_daily_sales_cost`, `dish_margin_variance`, `dish_ingredient_consumption`）；
  - 属于 `suppliers` 业务域的报表严格为 4 个（`receipts_itemized_ledger`, `supplier_payables_aging`, `supplier_payments_journal`, `supplier_recon_discrepancies`）；
  - 属于 `department` 业务域的报表严格为 2 个（`department_cost_summary`, `department_items_breakdown`）；
  - 每个元数据对象必须包含非空的 `id`, `category`, `category_name`, `title`, `description`, `filters` 字段。

### [AC-2] Excel 与 CSV 导出格式规范与 UTF-8 BOM 防乱码
- **GIVEN** 用户选择任意报表调用 `POST /api/export/download`；
- **WHEN** 客户端接收到导出的二进制字节流；
- **THEN** 数据流的前 3 个字节必须是标准的 UTF-8 BOM 标记（十六进制 `EF BB BF`）；
- **AND** 响应头 `Content-Type` 必须包含 `text/csv; charset=utf-8`；
- **AND** 响应头 `Content-Disposition` 必须采用 RFC 5987 标准对中文文件名进行安全编码（如 `filename*=UTF-8''%E5%AE%9E%E6%97%B6...csv`）；
- **AND** 在 Windows 中文版 Excel 与 Mac Numbers 中双击打开该文件，中文字符（含繁体字如「德利行」「鮮活海蝦」）100% 正常显示，无任何乱码或菱形问号。

### [AC-3] CSV 注入攻击防御与特殊字符安全转义
- **GIVEN** 数据库中存在特殊品名，如 `=cmd|' /C calc'!A0`、`+SUM(A1:A10)`、`"特级"生抽,带逗号`、带有换行符的备注；
- **WHEN** 导出包含上述内容的报表；
- **THEN** 生成的 CSV 中，首字符为 `=`, `+`, `-`, `@` 的字段前面必须自动被单引号 `'` 转义；
- **AND** 包含逗号或换行符的字段必须被双引号完整包裹；
- **AND** 原生双引号必须被规范转义为双重双引号 `""`，表格列结构绝对不可发生错位。

### [AC-4] 香港餐饮店员阿叔/阿姨极简交互与高压触控无障碍合规
- **GIVEN** 前端处于导出中心界面；
- **WHEN** 使用前端自动化评测工具审查 DOM 节点尺寸与样式计算；
- **THEN** 界面中所有关键交互按钮（包括顶部场景预置卡、分类 Tab、刷新按钮、打印按钮、导出 CSV 主按钮）的高度必须严格 `>= 38px`；
- **AND** 导出主按钮背景颜色（`#2563eb`）与文本颜色（`#ffffff`）的颜色对比度必须 `>= 4.5:1`，满足 WCAG 2.1 AA 级标准；
- **AND** 界面字体字号底线不低于 13px，核心指标汇总数字不低于 15px 且加粗，杜绝老花眼视线模糊看不清。

### [AC-5] 日期筛选防呆与倒置自动纠正机制
- **GIVEN** 用户在日期选择器中误将起始日期选为 `2026-08-31`，结束日期选为 `2026-08-01`；
- **WHEN** 用户离开输入框或触发预览/导出；
- **THEN** 系统不得抛出服务端 400 或 500 异常；
- **AND** 前端必须自动将起始日期重置为 `2026-08-01`，结束日期重置为 `2026-08-31`；
- **AND** 界面右上方弹出温和的人话提示：“检测到开单起始日期晚于结束日期，系统已自动帮您理顺顺序”，预览表格正常加载。

### [AC-6] 空数据状态人话直白展示 (杜绝技术黑话)
- **GIVEN** 过滤条件组合筛选出 0 条记录（如选择一个未来日期）；
- **WHEN** 调用预览接口 `POST /api/export/preview`；
- **THEN** 接口必须返回 HTTP 200 且 `preview_rows: []`, `total_rows: 0`；
- **AND** 预览表格区域必须展示平实通俗的人话占位：“在这个时间段内没有找到任何单据记录，请检查日期或切换分类”，绝对严禁出现 “Error: Empty Dataset”, "Null", "undefined" 等技术词汇。

### [AC-7] 实时预览抽样性能与大数据量流式响应门禁
- **GIVEN** 系统内存在超过 5,000 条收据行项目及出入库流水；
- **WHEN** 用户点击报表进行在线实时预览；
- **THEN** `POST /api/export/preview` 请求必须在 800ms 内完成响应，返回的 `preview_rows` 严格截断为前 15 行，并在表头右上角明确提示：“预览仅展示前 15 条抽样记录，完整数据请点击右上角导出”；
- **AND** 执行 `POST /api/export/download` 下载全量 5,000 行 CSV 时，服务端必须在 1.5s 内建立流式输出连接，不发生前端假死。

### [AC-8] 数据脱敏保护模式切换与字段级掩码一致性
- **GIVEN** 用户勾选了“数据脱敏保护 (隐藏供应商电话/品名隐私)”开关；
- **WHEN** 分别请求预览接口与下载接口；
- **THEN** 两个接口中输出的供应商名称（如“德利行 Tak Lee Hong”）必须被掩码转换为“德***行”；
- **AND** 供应商电话号码（如“91234567”）必须被掩码转换为“91****67”；
- **AND** 预览视图与 CSV 导出文件中的掩码转换规则必须保持 100% 逐字一致。

### [AC-9] 盘点底单现场打印与留白手填格式规范
- **GIVEN** 用户选中《实时库存盘点底单》(`inventory_stocktake`) 并点击“打印报表”按钮；
- **WHEN** 系统唤起浏览器独立打印窗口（`printWin`）；
- **THEN** 打印窗口必须渲染完整的 HTML 打印页面，包含标题、盘点统计汇总、打印当前时间戳；
- **AND** 盘点表格中必须包含 `实盘数量(现场手填)`、`盘盈/盘亏差异` 两列，单元格宽度预留充足空白供现场手写；
- **AND** 页面底部必须包含三项明确的下划线签字位：“经办人签字：_______________”、“主管审核签字：_______________”、“日期：_______________”。

### [AC-10] 财务核算与 FIFO 成本/毛利偏差计算精度规范
- **GIVEN** 请求《餐品理论毛利 vs 真实毛利偏差诊断表》或《每日销售与食材实际成本汇总表》；
- **WHEN** 服务端核算理论成本、实际成本、毛利率与毛利侵蚀点；
- **THEN** 所有金额字段必须使用四舍五入精确至小数点后 2 位；
- **AND** 毛利率必须满足公式：`毛利率 = ((营业额 - 实际成本) / 营业额) * 100`（保留 1 位小数）；
- **AND** 当营业额为 0.00 时，毛利率必须安全输出为 `0.0%`，严禁抛出除以零异常；
- **AND** 报表底部的合计金额必须严格等于各明细行金额之和，代数绝对误差 `<= 0.01`。

### [AC-11] 多租户数据物理/逻辑强隔离门禁校验
- **GIVEN** 登录用户属于租户 `tenant_A`；
- **WHEN** 用户在请求报表参数中伪造传递属于 `tenant_B` 的 `supplier_id` 或 `department_id`；
- **THEN** 服务端在数据提取层必须强制绑定上下文中的 `tenant_id`，绝对不得查询、计算或泄露 `tenant_B` 的任何单据、品名、成本或出入库流水；
- **AND** 跨租户参数必须被自动过滤，返回结果集严格为 0 条或仅限 `tenant_A` 的内部数据。

### [AC-12] 角色权限控制与店员/老板越权阻断
- **GIVEN** 当前登录用户角色为前线店员 (`staff`)；
- **WHEN** 店员在数据导出中心使用报表导出功能；
- **THEN** 店员允许正常预览与导出《实时库存盘点底单》、《出入库全量流水综合台账》等生产作业报表；
- **AND** 如果后台配置了敏感报表门禁（如老板专属的《部门采购花销期间环比对照表》），当未经授权的角色尝试访问时，系统必须返回清晰的人话权限指引：“当前角色为店员，此报表需老板或管理人员权限查看”，严禁返回裸露的 403 英文代码页。
