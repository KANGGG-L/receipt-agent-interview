## 一、目的与边界

### 1.1 目的

在**不新增语义标签**的前提下，对每张已准入的真实单据父本（canonical）施加一组**冻结、可复现**的图像变换，模拟后门收货场景中的歪斜、明暗、模糊、裁边等失真，用于：

1. **鲁棒性回归**：管线在变体上是否仍能跑通（不崩溃、不卡死、失败路径显式）；
2. **分桶诊断**：哪类失真（旋转 / 亮度 / 对比度 / 模糊 / 裁剪）最伤识别；
3. **与生产输入对齐**：增强输出格式贴近线上 S1（长边上限、JPEG 质量）。

### 1.2 非目标

| 不做 | 理由 |
| :--- | :--- |
| 水平 / 垂直**翻转**进入 L1 | 镜像后文字方向与真实拍摄习惯不符，易造成「假失败」；翻转不进 L1（已拍板） |
| 用增强图扩充语义覆盖（新供应商/新品名） | 语义仍以父本为准；增强只改成像 |
| 默认要求字段级 F1 / 全对率 | **expected 策略 = 可跑通、不崩溃**（见 §三） |
| 把大图强制提交进 git | 落盘默认在可配置的外部目录（如 Google Drive） |

### 1.3 核心原则

1. **父本唯一**：增强图不得再当 parent 二次增强。  
2. **确定性**：同一 `(source_id, recipe_id, seed, tool_version)` → 可复现（算法与参数写死）。  
3. **继承元数据**：`supplier`、授权、归类信息继承父本；不伪造 expected 字段。  
4. **失败显式**：生成失败或门禁拒绝 → 记入报告，不静默丢弃无痕。

## 二、`supplier_cap` 是什么（规模模式）

增强会**按父本张数 × 每图 recipe 数**膨胀体积。例如 163 张 × 8 条 L1 ≈ **1304** 张，Drive 空间与评测耗时都不可忽视。因此用 **规模模式（scale mode）** 控制「选多少父本」：

| 模式 | 含义 | 父本怎么选 | 典型体量（×8 recipes） | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| **`pilot`** | 冒烟 | 全局抽极少张（如 3–5）或每供应商 1 张 | ~24–80 | 验脚本/路径/门禁 |
| **`supplier_cap`（默认）** | **每供应商上限** | 每个供应商最多取 **K** 张父本（默认 **K=5**），再对选中父本做满 8 条增强 | 12 供应商 ×5 ×8 ≈ **480** | **日常回归推荐** |
| **`full`** | 全量 | batch 内全部合规父本 | 163×8 ≈ **1304** | 发布前压力 / 专项分析 |

### 2.1 `supplier_cap` 直观解释

- **问题**：batch1 里「新協興」有 78 张、「永樂烘焙」只有 1 张。若 `full`，增强集几乎被头部供应商淹没，尾部供应商几乎测不到多样性。  
- **做法**：对每个 `supplier` 文件夹（或 manifest 分组）**最多选 K 张**作为 canonical 父本（选取规则见 §2.2），再对这 K 张各自生成 8 条 L1 变体。  
- **效果**：
  - 控制总张数与评测时间；
  - **供应商维度更均衡**（每家都有代表样本）；
  - 仍覆盖「多家供应商 × 多种失真」，而不是「一家供应商刷屏」。

```
示例（K=5，batch1 12 家供应商）：
  新協興 78 张 → 只取 5 张父本 → 5×8 = 40 张增强
  德利行 27 张 → 只取 5 张父本 → 40 张增强
  永樂烘焙 1 张 → 取 1 张父本 → 8 张增强
  …
  合计父本 ≤ 12×5，增强 ≤ 父本数×8
```

### 2.2 父本选取规则（`supplier_cap` / `pilot` 共用纪律）

在同一供应商内选取父本时，按以下**确定性**顺序（禁止纯随机无 seed）：

1. 排除门禁不合格原图（损坏、过小、无法解码）；  
2. 优先 `classification_manifest.csv` 中 `confidence=high`；  
3. 按 `filename` **字典序**取前 K 张（可复现）；  
4. 可选：同一供应商内按文件序号**均匀抽样**（stride），参数写入 PROFILE，默认实现可用「字典序前 K」以简单为准。

`K` 由环境变量或 CLI 覆盖，默认 **5**（见 §六）。

## 三、expected 策略：可跑通、不崩溃

本阶段增强集的**主验收不是字段级准确率**，而是：

| 层级 | 通过条件 | 说明 |
| :--- | :--- | :--- |
| **P0 进程** | 处理单张不抛未捕获异常；超时有上限 | 防卡死 |
| **P0 状态** | 结束态为 `parsed` / `error` / 显式 skip 之一，**不得**永卡 `uploaded`/`parsing` | 与 D28 纪律一致 |
| **P0 响应** | HTTP/Job 有终态；error 时带 `receipt_id` 或等价可追溯 ID（若走 API） | 失败可查 |
| **P1 软指标（观察）** | 解析成功率、error 率、耗时 P95，按 `recipe_id` 分桶 | 不设硬门槛直至有基线 |
| **非目标（本阶段）** | 字段 F1、全对率、与 expected JSON 逐字段比对 | 待父本具备覆核 GT 后再开 `profile=with_gt` |

父本**可以没有** `expected/*.json`。manifest 中 `expected_ref` 允许为空；评测适配器只跑 pipeline / adapter，断言「可完成 + 不崩溃」。

## 四、L1 标准配方（8 条，已全部采纳）

**L1 不含任何翻转（flip）。** 旋转仅使用 90° 的倍数中的 90°/270°（横拍常见）；180° 留 L2。

| # | `recipe_id` | 处理说明 | 参数（冻结） |
| ---: | :--- | :--- | :--- |
| 1 | `rot90` | 逆时针 90°（或 Pillow `rotate(90, expand=True)`，**整图旋转**，背景不补黑边语义以 expand 为准） | angle=90° |
| 2 | `rot270` | 逆时针 270°（等价顺时针 90°） | angle=270° |
| 3 | `bright_down` | 降低亮度 | 像素线性乘 **0.70**，再 clip 到 [0,255] |
| 4 | `bright_up` | 提高亮度 | 乘 **1.30**，clip |
| 5 | `contrast_down` | 降低对比度 | 相对中灰 128：`out = (in-128)*0.75 + 128`，clip |
| 6 | `contrast_up` | 提高对比度 | 系数 **1.25**，同上 |
| 7 | `blur_light` | 轻度高斯模糊 | `GaussianBlur`，**radius=1.0**（约 σ≈1） |
| 8 | `crop_center_85` | 中心裁剪后缩放回原尺寸 | 保留中心 **85%** 宽与高，再 resize 回父本输出尺寸 |

### 4.1 处理顺序（单 recipe）

每条 recipe **只施加上表中一种主变换**（不做多变换叠加），保证归因清晰：

```
父本解码 → RGB 工作图 → [单一 recipe 变换] → 统一导出编码 → 门禁 → 落盘
```

### 4.2 统一导出编码（所有 L1 输出）

与生产 S1 / D24 对齐，便于对比：

| 项 | 值 |
| :--- | :--- |
| 色彩 | RGB |
| 格式 | JPEG |
| 质量 | **85** |
| 长边 | **≤ 1600**（只缩小不放大；短边同比） |
| 色彩管理 | 忽略复杂 ICC；按当前 RGB 直接存 |

HEIC 父本：入口可用 macOS `sips` 或 Pillow+插件转为工作 RGB，再进 recipe；**最终产物统一 JPEG**。

### 4.3 L2 预留（本文不实现为默认）

可后续扩展：`rot180`、小角度旋转、边缘裁剪、JPEG q=40、锐化、加噪、透视、**水平翻转（单独桶）** 等。L2 不得与 L1 recipe_id 混名。

## 五、端到端规范性流程

```
0. 准入 Gate
     │  父本可读；已有 supplier 归类（推荐 classification_manifest）
     ▼
1. 选择规模模式 + 选取父本列表
     │  默认 supplier_cap（K=5）
     ▼
2. 对每个父本 × 每个 L1 recipe
     │  解码 → 变换 → 导出编码
     ▼
3. 生成后门禁
     │  过暗/过小/坏文件 → reject + 记日志
     ▼
4. 落盘到 AUG_OUTPUT_ROOT（环境变量）
     │  images/ + meta/ + manifest 增量
     ▼
5. 校验
     │  父本数×8 = 成功数 + 拒绝数；无孤儿 meta
     ▼
6. 评测接入（可跑通/不崩溃）
     │  按 recipe_id / supplier 分桶报告
     ▼
7. 归档 PROFILE 快照（参数冻结副本）
```

### 5.1 步骤说明

**0. 准入**  
- 输入源默认：batch 根目录或 `by_supplier/*`。  
- 跳过：`_previews/`、已是增强产物目录、非图像扩展名。

**1. 选父本**  
- 读 `SCALE_MODE`（默认 `supplier_cap`）与 `SUPPLIER_CAP_K`（默认 5）。  
- 产出 `parents.csv`（本次 run 的父本清单），便于审计。

**2. 变换**  
- 实现须与 §四参数一致；`tool_version` 写入每条 meta（git commit 或脚本版本号）。

**3. 生成后门禁（默认阈值）**

| 检查 | 阈值 | 动作 |
| :--- | :--- | :--- |
| 解码失败 | — | reject |
| 短边 | < 400 px | reject |
| 灰度均值 | < 25 或 > 240 | reject |
| 文件大小 | < 2 KiB | reject |
| 与父本导出后完全一致（可选） | 字节相同 | reject（增强无效） |

门禁失败：**不写 images 成功路径**，在 `rejects.csv` 留 `source_id, recipe_id, reason`。

**4–5. 落盘与校验**  
见 §七目录约定。

**6. 评测**  
- 对每张增强图调用现有 pipeline 或 eval adapter（允许 skip 引擎缺失）。  
- 断言：进程退出 0 或捕获为业务 error；**禁止**裸 traceback 作为「通过」。  
- 汇总：`ok / error / timeout / reject_gen` 计数 × `recipe_id`。

## 六、环境变量与配置

落盘根目录**不得写死**本机 Google Drive 路径；统一由环境变量注入。

| 变量 | 必填 | 默认 | 含义 |
| :--- | :---: | :--- | :--- |
| **`AUG_OUTPUT_ROOT`** | 推荐 | 无（未设则拒绝写盘或仅 dry-run） | 增强集输出根目录。Google Drive 示例见下 |
| **`AUG_INPUT_ROOT`** | 否 | 见运行参数 | 父本 batch 根目录 |
| **`SCALE_MODE`** | 否 | `supplier_cap` | `pilot` \| `supplier_cap` \| `full` |
| **`SUPPLIER_CAP_K`** | 否 | `5` | `supplier_cap` 时每供应商最多父本数 |
| **`AUG_PROFILE`** | 否 | `standard` | 目前仅 `standard`=L1 八条 |
| **`AUG_SEED`** | 否 | `42` | 全局种子；单条 recipe 实际 seed = hash(source_id, recipe_id, AUG_SEED)（L1 八条均无随机，预留给 L2） |
| **`AUG_LONG_EDGE`** | 否 | `1600` | 导出长边上限 |
| **`AUG_JPEG_QUALITY`** | 否 | `85` | JPEG 质量 |

### 6.1 Google Drive 示例（本机）

```bash
export AUG_OUTPUT_ROOT="/Users/ethan/Library/CloudStorage/GoogleDrive-pgmhkai@gmail.com/My Drive/Receipts/aug_sets"
export AUG_INPUT_ROOT="/Users/ethan/Library/CloudStorage/GoogleDrive-pgmhkai@gmail.com/My Drive/Receipts/batch1"

export SUPPLIER_CAP_K=5
```

- 换机器 / 换 Google 账号：只改 `AUG_OUTPUT_ROOT` / `AUG_INPUT_ROOT`。  
- CI 或无 Drive 时：可指到本地 `~/receipt_aug` 或 tmp，**同一套脚本**。  
- 未设置 `AUG_OUTPUT_ROOT`：脚本应 **exit 非 0** 或强制 `--dry-run`，禁止静默写到仓库目录。

## 七、目录与命名约定

在 `AUG_OUTPUT_ROOT` 下按 **run** 隔离（避免覆盖）：

```
$AUG_OUTPUT_ROOT/
  runs/
    {run_id}/                          # 建议：{date}_{profile}_{scale}_k{K}
      PROFILE.md                       # 本次冻结的 recipe 表与 env 快照
      parents.csv                      # 入选父本
      manifest.csv                     # 成功产物清单
      rejects.csv                      # 门禁/解码失败
      images/
        {source_id}__{recipe_id}.jpg
      meta/
        {source_id}__{recipe_id}.json
      reports/                         # 评测分桶结果（可选后续）
        smoke_summary.md
```

### 7.1 `source_id`

- 推荐：`batch1_IMG_5786`（`{batch}_{stem}`，stem 去扩展名、统一大写序号习惯可保留原名）。  
- 禁止路径分隔符与空格。

### 7.2 图像文件名

```
{source_id}__{recipe_id}.jpg
# 例：batch1_IMG_5786__bright_down.jpg
```

### 7.3 `meta/*.json` 最小字段

```json
{
  "source_id": "batch1_IMG_5786",
  "parent_path": ".../batch1/IMG_5786.HEIC",
  "recipe_id": "bright_down",
  "profile": "standard",
  "ops": [{"op": "brightness", "factor": 0.7}],
  "export": {"format": "jpeg", "quality": 85, "long_edge": 1600},
  "supplier": "新協興",
  "seed": 42,
  "tool_version": "aug-v1.0",
  "created_at": "2026-08-05T12:00:00+08:00"
}
```

### 7.4 `manifest.csv` 表头

```
source_id,parent_filename,supplier,recipe_id,profile,scale_mode,image_relpath,meta_relpath,expected_ref,status,notes
```

- `expected_ref`：本阶段固定为空或 `none`。  
- `status`：`ok` \| `rejected`（成功行一般为 ok；拒绝以 rejects 为准也可只出现在 rejects）。

## 八、图像处理技术说明（实现指引）

### 8.1 解码

| 格式 | 建议 |
| :--- | :--- |
| JPEG/PNG | Pillow `Image.open` → `convert("RGB")` |
| HEIC | 优先 `sips -s format jpeg` 到临时文件再 Pillow；或 `pillow-heif` 注册后打开 |

### 8.2 各 recipe 伪代码

```text
# rot90 / rot270
img = img.rotate(angle, expand=True)   # angle in {90, 270}

# bright_*
arr = np.asarray(img).astype(np.float32) * factor
arr = clip(arr, 0, 255).astype(uint8)

# contrast_*
arr = (arr - 128.0) * factor + 128.0
arr = clip(arr, 0, 255)

# blur_light
img = img.filter(ImageFilter.GaussianBlur(radius=1.0))

# crop_center_85
w, h = img.size
cw, ch = int(w * 0.85), int(h * 0.85)
left, top = (w - cw) // 2, (h - ch) // 2
img = img.crop((left, top, left+cw, top+ch)).resize((w, h), LANCZOS)
```

导出前统一：

```text
fit_long_edge(img, AUG_LONG_EDGE)  # 仅当 max(w,h) > long_edge
img.save(path, format="JPEG", quality=AUG_JPEG_QUALITY, optimize=True)
```

### 8.3 与生产 S1 的关系

| 生产 S1（`image_preprocess`） | 本增强流程 |
| :--- | :--- |
| EXIF 扶正、HEIC 策略、长边 1600/q85 | 增强**导出**对齐 1600/q85，便于公平 |
| 质量预检非阻断 | 增强**生成门禁**可更严（过暗直接 reject） |
| 不在 S1 做旋转 90 测试 | L1 用 `rot90`/`rot270` **主动造**歪图，测上游是否依赖朝向 |

增强集测的是「坏成像输入」；生产 S1 测的是「尽量规范化输入」。二者互补，不互相替代。

## 九、评测接入（可跑通口径）

### 9.1 最小断言（单张）

```text
result = run_pipeline_or_adapter(image_path)  # 或 subprocess 超时包装
assert not uncaught_exception
assert finished_within_timeout
assert terminal_status in {parsed, error, skipped}
# 不要求 predicted 与 GT 一致
```

### 9.2 报告分桶

- 按 `recipe_id`：ok 率、error 率、超时率、平均耗时  
- 按 `supplier`：同上  
- 可选：与「同父本未增强（若另跑 L0）」对比 error 率差  

### 9.3 与 T11 / 黄金样本

- 黄金样本（字段 F1）仍走 `samples/` + expected JSON。  
- 本增强集是 **独立 split**（如 `aug_standard`），指标集不同，**禁止**与 holdout 字段 F1 混报成同一张「准确率」表。

## 十、运行示例（已实现）

脚本：`scripts/augment_receipts.py`（tool_version `aug-v1.0`）。

```bash
export AUG_OUTPUT_ROOT="…/My Drive/Receipts/aug_sets"
export AUG_INPUT_ROOT="…/My Drive/Receipts/batch1"
export SCALE_MODE=supplier_cap
export SUPPLIER_CAP_K=5

# 仅生成
./venv/bin/python scripts/augment_receipts.py generate

# 生成 + 成像冒烟（解码 + 门禁，不跑 OCR）
./venv/bin/python scripts/augment_receipts.py generate --smoke

# dry-run：只打印父本列表与将写路径
./venv/bin/python scripts/augment_receipts.py generate --dry-run

# OCR 冒烟：真正 process_receipt_pipeline（可跑通/不崩溃）
export QWEN_VL_MODEL=qwen-vl-plus   # 与型号配置一致，勿写死在代码
./venv/bin/python scripts/augment_receipts.py ocr-smoke \
  --run-dir "$AUG_OUTPUT_ROOT/runs/<run_id>" \
  --engine qwen --per-recipe 2
# 全量：--per-recipe 999 或 --limit 0 且提高 per-recipe
```

batch1 首轮实测（2026-08-05）：`supplier_cap` K=5 → **47 父本 × 8 = 376 张**，rejects=0，成像 smoke 376/376 ok。  
OCR 冒烟（同日）：`--engine qwen --per-recipe 2` → **16/16 ok，0 crash**，报告在 `runs/<id>/reports/ocr_smoke_*`。  
产物目录：`$AUG_OUTPUT_ROOT/runs/<run_id>/`。
