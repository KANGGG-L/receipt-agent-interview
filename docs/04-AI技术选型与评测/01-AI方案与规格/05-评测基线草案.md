## 三、头号发现：CodeBuddy 引擎当时不可用（2026-08-08 快照）

- **现象**：CodeBuddy 处理整张收据图（长 prompt + 读图）单次 **>45s 超时**，全部失败；管线每次白耗 ~90–100s 后 qwen 兜底。批1 审计 `audit_engine_stats` 亦证实：codebuddy 22 次调用 **0 成功**。
- **处置（已落地）**：`CALL_TIMEOUT_SECONDS` 45s → **180s**（codebuddy_runner.py）。简单 prompt 22s 能回、长 OCR prompt 超 45s，说明 45s 过紧，180s 是合理放松。
- **待办**：180s 生效后需**重跑 codebuddy 引擎基线**验证是否可用；若仍失败，需排查 CodeBuddy CLI 读图路径/权限/模型加载，或降级「codebuddy 仅作审核引擎」。

## 四、粗糙基线的局限（诚实声明）

1. **expected 为 AI 草稿**：行级错位 → 明细缺失/多余双惩罚，PASS 率被显著压低。7/57 PASS 不代表真实识别率。
2. **行匹配算法宽松**：`_compare` 用子串/相似度 ≥0.8 匹配，仍把「數量 6 vs 1」「单价 1.8 vs 70」这类真实错误记为字段不符——这部分是**真错误**，可信。
3. **形态覆盖偏斜**：57 张 = 38 delivery_note + 16 statement + 3 thermal_receipt；街市手写/磅单/更正/贷记**零样本**，产品差异化场景（手写单）未覆盖。
