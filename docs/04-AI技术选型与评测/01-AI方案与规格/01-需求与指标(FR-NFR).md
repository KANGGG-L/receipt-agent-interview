> 更新：2026-08-03 · 状态：定稿

> 需求来源：`../01-业务流程.md`（七种单据形态、印章/手写付款标记、粤语俗称与司马斤、现结/月结双轨）

## 一、定位与边界

AI 子系统是链路中的**感知层**：把非结构化的单据照片变成结构化数据与分类信号。

| AI 负责 | AI 不负责（确定性代码层） |
| :--- | :--- |
| 图像 → 结构化字段抽取 | 算术正确性（数量×单价=金额、Σ=总额） |
| 单据形态/结算方式/付款标记分类 | 单位换算、SKU 别称匹配 |
| 逐字段置信度估计 | 价格异动检测、对账匹配 |
| 供应商记忆上下文利用 | 库存台账、支付核销 |

原则：**AI 输出的任何数字，未经代码门禁校验不得入库**（详见 `../05-技术方案.md` T4）。

## 二、功能需求（FR）

| # | 需求 | 说明 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR-1** | 基础结构化抽取 | 从单据照片提取：供应商名、开单日期、归档月份、总金额、明细行（品名/数量/单位/单价/金额） | P0 |
| **FR-2** | 七种单据形态识别 | 判定 `doc_form`：印刷送货单 / 街市手写单 / 热敏机打 / 磅单 / 更正单 / Credit Note / 月结账单，并按形态走对应识别模板 | P1 |
| **FR-3** | 无表格手写单抽取 | 街市 NCR 手写单大量**无表格 schema**（一行一物、无列对齐）：必须按"行语义"抽取，不得预设表格结构 | P1 |
| **FR-4** | 结算方式分类 | 判定 `settlement_type`：现结（现金单）/ 月结（赊单），依据"月结/赊/收妥"印刷或手写标记 | P1 |
| **FR-5** | 付款标记检测 | 判定 `payment_mark`：印章（收讫/PAID，红色、可旋转、**可覆盖明细文字**）/ 手写批注（收妥/已收）/ 仅签名 / 无；**印章文字不得污染明细抽取**；手写批注词（收妥/已收/已付/月结/赊/过数）不得成为明细行 | P1 |
| **FR-6** | 算术自洽校验 | `数量×单价=金额`、`Σ明细=总金额`；不一致时自动修正并告警；AI 单方面算出的金额不允许绕过校验 | P0 |
| **FR-7** | 港式归一化 | 繁简归一、粤语别称映射（走地雞→鲜鸡）、司马斤(0.605kg)/两/磅折算；计件单位（包/罐/件）不折 kg；支持按供应商记录单位基准差异 | P0/P1 |
| **FR-8** | 逐字段置信度 | 明细行级 confidence（0–1）回传，驱动门控路由：高置信直通、中置信复核、低置信重拍/换引擎 | P2 |
| **FR-9** | 供应商记忆注入与进化 | 识别时注入该供应商的排版习惯/单位惯式/few-shot（数据与指令隔离）；FER、重拍、flag 信号驱动记忆增量更新；防错误记忆自我强化 | P2 |
| **FR-10** | 修订注记识别 | 验货时手写的拒收/短装注记（"缺 2 斤""退回 1 箱"）单独抽取为 `adjustment_notes`，不混入正常明细 | P2 |
| **FR-11** | 月结账单抽取 | 汇总表格 → 行数组（日期/单号/金额）+ 小计 + 上期结余 + 本期应付；算术引擎校验 `∑每笔 ± 调整 = 本期应付` | P2 |
| **FR-12** | 双引擎与显式降级 | CodeBuddy CLI 优先（零 API 成本）→ Qwen-VL 降级；**两引擎皆败时必须显式报错**，禁止静默返回空结构假装成功 | P0 |

## 三、非功能需求（NFR）

| # | 需求 | 指标/约定 |
| :--- | :--- | :--- |
| **NFR-1** | 成本 | MVP 阶段近零 API 成本（CodeBuddy 本地优先）；token 计量必须来自真实读数，禁止估算假值 |
| **NFR-2** | 时效 | OCR 异步化，不阻塞 HTTP；单张目标 P95 ≤ 60s；批量串行受限但进度可查 |
| **NFR-3** | 可靠性 | 失败显式化（status=error，可重试）；不得卡在中间态；重跑幂等；同一图像去重（pHash） |
| **NFR-4** | 安全 | 防间接提示词注入：记忆数据与指令隔离（XML 包裹 + system 声明）、输出 JSON Schema 契约、记忆写入净化、解析收紧（首个 `{` 配对截取而非贪婪正则）、文件名净化 |
| **NFR-5** | 可观测 | 每张单据 trace_id；分阶段耗时（OCR/算术/匹配/审计）；记忆命中与否；引擎调用与真实 token 统计 |
| **NFR-6** | 合规 | 原图与识别结果满足 7 年税务留存；备份策略覆盖 DB 与 uploads |

## 四、需求 → 验收映射

对应 `../05-技术方案.md` 第六节端到端 DoD：

| DoD 条目 | 覆盖需求 |
| :--- | :--- |
| 1 真实港式收据识别 + 算术门禁 | FR-1、FR-6、FR-7 |
| 2 ≥80% SKU 匹配（含别称） | FR-7 |
| 3 无表格手写单行语义抽取 | FR-3 |
| 4 印章现金单判定且不污染明细 | FR-4、FR-5 |
| 8 月结账单 OCR 成行 + 对账 | FR-11 |

NFR 验收：成本看板基于真实 token（NFR-1）；异步 job 可轮询（NFR-2）；失败单据可重试且不重复建单（NFR-3）。
