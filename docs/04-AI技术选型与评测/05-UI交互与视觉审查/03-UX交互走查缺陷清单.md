# 实时库存与价格 · 实机体验发现

> 探查时间：2026-08-05  
> 环境：`http://localhost:15000`（进程内 API 与磁盘前端**不一致**）  
> 截图：`eval/browser_screenshots/ux_inventory/`

## 结论（老板视角一句话）

页面已经「看起来像能管料表」（有搜索、新增、编辑、停用），但**点下去后端对不上**，价格走势几乎没信息，库存全是演示绿数字——**仍然不像我的店，也不敢当真用。**

---

## P0 · 会直接放弃 / 功能不可用

### 1. 前后端不同步（最严重）
| 操作 | 前端 UI | 当前运行中 API |
| :--- | :--- | :--- |
| 新增食材 | 有「+ 新增食材」按钮 | `POST /api/inventory/skus` → **404** |
| 编辑档案 | 行内「编辑」 | `PATCH /api/inventory/skus/{id}` → **404** |
| 搜索 `?q=` | 有搜索框 | 运行中进程未吃 query（或异常） |
| 涨价预警 | 指标卡有 | 列表 JSON **无** `price_anomaly` / `meta` |

磁盘代码里已有 `services/sku_service.py`、`migrations/017_*`、改过的 `app.py`，但 **15000 端口进程是旧后端**。  
用户体验 =「按钮是假的」→ 信任崩塌。

### 2. 演示库存「全绿假繁荣」
- API：60 个 SKU，**低库存 = 0，零库存 = 0，涨价 = 0**
- 账面 min=3kg、max=200kg，全部 `is_low_stock=false`
- 老板第一眼：系统说「一切正常」，但那是**种子演示数**，不是冷柜实数
- 无「请用盘点校准」提示条（HTML 无 invHint / 盘点提示）

### 3. 价格走势几乎无决策价值（种子态）
- 鲜鸡：仅 **1 笔「基准单价」**，供应商「—」，单据「—」
- 日期被截断成 `2026-07-...`
- 曲线一条水平线 + 假纵轴 $39.4–$50.6（单点硬撑高度）
- 副标题仍暴露 `SKU_MEAT_CHICKEN`（主表已隐藏代码，Modal 又甩出来）
- 脚注很长、术语多（台账 / 阈值），无技术用户不会读

## P1 · 能用但很烦 / 不专业

### 4. 指标卡中英混排
- `Total SKUs` / `Reorder Alert` / `Price Anomaly`
- 第三卡已从「匹配率 100%」改成涨价预警（进步），英文括号仍在

### 5. 指标卡「全 0」且可点筛选意义弱
- 低库存 0、涨价 0：点卡筛选得到空表或全表，**没有正向反馈**
- 种数 60 对「我只做茶餐厅」过多，助长噪音感

### 6. 操作列过重
- 每行 **4 个控件**：价格走势 | 盘点 | 编辑 | 更多
- 窄屏/小笔电易挤；「更多」里才是记用量/报损耗/停用

### 7. 盘点弹窗仍像内部工具
- 标签写 **「SKU：鲜鸡」**（用户不懂 SKU）
- 脚注：`stocktake_adjust 台账留痕` — 开发者语言
- 预填实盘=账面 25，一键确认等于无操作（易误触「假盘点」）

### 8. 无开业/校准引导（方案 B 要求的 hint 未见）
- 产品拍板「只做逐条盘点」，但界面**没告诉新店主「数字是演示的、请逐条盘点」**

### 9. 分类/料表与「我家店」错位
- 含象拔蚌、牛眼肉、羊肉片等；茶餐厅老板会觉得「这不是我的菜单」
- 有「显示已停用」但默认 60 条全启用，停用成本高（逐条更多→停用）

## 建议优先修复顺序（体验向）

1. **重启/热加载后端**使 017 + sku CRUD + inventory meta/筛选真正生效（否则 UI 全是空壳）  
2. **新店数据策略**：种子库存改为 0，或首屏强提示「演示数据，请盘点校准」  
3. 盘点文案去 `SKU`/`stocktake_adjust`  
4. 价格走势：无真实进货时的空态文案（「还没有审核入库记录」）而非假曲线  
5. 指标卡去掉英文；种数旁可显示「启用中」  
6. 操作列收纳（主：盘点/编辑；次：走势进更多或图标化）
