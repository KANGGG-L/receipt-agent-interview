## 一、L0–L9 选型实测总表（163 张真实收据 · 2026-08-09）

| 阶梯 | 路径与最佳配置 | 成功率 | P50 耗时 | 消耗 Tokens | 估算成本 (RMB) | 决策结论 |
| :---: | :--- | :---: | :---: | :---: | :---: | :--- |
| **L0** | Tesseract + 正则规则 | 3.1% | 3.4s | 0 | ¥0.00 | [ALERT]  **否决**（无法解析复杂排版与繁体手写） |

| **L5** | 多模态 + 3 模板路由 | 78.5% | 13.0s | 616k | ¥0.37 | [ALERT]  **否决**（多轮调用带来级联错误） |
| **L6** | 多模态 + 交叉审核 Agent | 82.2% | 17.2s | 965k | ¥0.34 | [WARN]  **条件启用**（Token 翻倍，仅高疑点单触发） |
| **L7** | 看想分离（OCR 专用读图 + LLM） | 26.4% | 9.5s | 379k | ¥0.48 | [ALERT]  **否决**（丢失版面空间语义，结构化能力崩塌） |

## 二、核心决策摘要

1. **主生产路径**：全面采纳 **L4 云端多模态 VLM 直识（`qwen3-vl-flash`）**，兼顾 100% 成功率与单张约 ¥0.0022（2.4 港仙）的极低成本。
2. **离线私有化兜底**：采用 **L1/L2 本地 PaddleOCR + 结构化 LLM** 作为无公网环境下的保底方案。
3. **架构避坑论证**：
   - 彻底否决 **L7 看想分离**（专有 OCR 识别纯文本后交由 LLM 拼接，严重破坏香港餐饮单据多列、手写、印章的空间关联）。
   - 彻底否决 **L5 模板分类前置路由**（分类模型置信度不足会引发级联错误，单轮端到端多模态效果更优）。
